### 寫到阿瓦隆百科試算表（預設）

**聊天紀錄寫進阿瓦隆百科試算表，只留最近 7 天，發言者代號每天重新編號——這是 Edward 2026-10-13 的決定**
（「不用搬到私人試算表 搬到 阿瓦隆百科 googlesheet 就好 然後最多保留近一週的即可」；被告知這份公開之後：「照搬 百科群組本身也是公開的 所以不影響」）。
程式預設就寫這份，Render 不用設任何變數。

- 阿瓦隆百科那份（`174L-by-dtP6IY1pRy8nMpG6_3RMBQXmAV4kTfIgmyIU`）是「**知道連結的任何人都能檢視**」，
  而且它的 id 就寫在這個公開 repo 裡（戰績快取每天從它重算）——等於**任何人都能打開**。
- 所以任何人都能翻到最近 7 天的群聊原文。發言者是代號、每天從「成員1」重新編號，但**內文裡提到的名字、私事、約打的時間地點都看得到**；
  也有人可能每天存一份，所以「只留 7 天」只限制試算表本身，不保證外面沒有副本。
- 那份的分享設定若改成「限定的使用者」，聊天就不再公開（戰績快取與牌譜匯入用服務帳號讀寫，不受影響）；但它公開是給社群查資料用的，要不要改由 Edward 決定。
- 狀態頁 `chatExport.publicSheet=true` 就是正在寫這份。Render 上的服務帳號 JSON 和每日牌譜匯入用的是同一個 GitHub secret（`AVALON_STATS_SHEETS_CREDENTIALS_JSON`），
  那個帳號本來就在寫這份的「Discord匯入」分頁，通常不用再分享；若 `lastRun.outcome` 是 `sheet-error` 再確認一下。
- 寫在這份時**只動「聊天紀錄」「匯出紀錄」兩個分頁**（不存在就新增在最後面）：不讀、不寫、不刪「牌譜」「Discord匯入」「Discord回覆」「同贏」…
  任何其他分頁（每日牌譜匯入與戰績快取在讀它們；有測試確認）。如果已經有一個叫「聊天紀錄」或「匯出紀錄」、但標題列不一樣的分頁，
  bot 判定那不是它的，**兩個分頁都不碰**，狀態頁 `outcome=tab-conflict`。
- 阿瓦隆百科那份在部署後會自動補齊最近 7 天。私人那份從 20261013h 起是閱讀副本（見下一節）：裡面原本就有的「聊天紀錄」「匯出紀錄」分頁會被閱讀副本接著用，
  早期版本寫的日子會自動重寫（不用手動刪）。

### 閱讀副本（私人那份的第一個分頁）

**閱讀副本存在的唯一理由，是讓 AI 管理員讀得到聊天。** 內容和阿瓦隆百科那份的「聊天紀錄」**完全一樣**（同樣的列、同樣的日子、同樣只留最近 7 天），
只是另外放在一份小的私人試算表，而且「聊天紀錄」固定是那份的**第一個分頁**。

- 為什麼需要（2026-10-13 實測）：AI 管理員讀 Google 檔案只能透過 Google Drive 連接器——
  讀阿瓦隆百科那份只會拿到第一個分頁「牌譜」的大約 40 列樣本，讀不到「聊天紀錄」；整份下載成 xlsx 又太大；
  但連接器可以把一份試算表的**第一個分頁**下載成 CSV（Drive 匯出 `text/csv`）。所以聊天要在一份小試算表的第一個分頁，AI 管理員才讀得到。
- 寫在哪：預設私人那份 `1k-ZNYqCnnS__Oc-NLX_ciVmaHOnBwilHbFjXeE5orx8`（Edward 擁有，服務帳號已是編輯者）。
  `CHAT_EXPORT_READING_COPY_SHEET_ID` 可以改成別份（id 或網址；那份要分享給服務帳號當編輯者），`off` 關閉。
- 只動兩個分頁：「聊天紀錄」（建立在第一個位置；被拖到別的位置，下次執行時移回第一個——只改位置）和它自己的「匯出紀錄」（放最後面）。
  移回第一個是「盡量」：Google 拒絕移動時（例如分頁被保護），照樣寫入、照樣刪 7 天以前的列，server log 記一行
  `chat tab not moved to the first position (…HTTP 狀態碼…)`，下次執行再試——這段期間 CSV 拿到的可能不是聊天，把分頁拖回第一個或解除保護即可。
  **「練習回報」**（練習模式回報，`src/practice/PracticeReportWriter.ts` 在寫）**不讀、不寫、不刪**；
  Google 建立試算表時留下的空白「工作表1」也留著不刪（它會被擠到第二個，不影響 CSV）。
- 和阿瓦隆百科那份**完全一樣的規則**：每天 04:30 起寫前一天、重啟後補齊最近 7 天、「匯出紀錄」的進行中／完成、清理鎖、只留 7 天、
  `CHAT_EXPORT_ENABLED=false` 時只刪 7 天以前的列。程式上是第二個匯出服務：自己那份的進行中／完成、自己的重試、自己的狀態。
- **Discord 通常只讀一次**：兩邊在同一分鐘跑，同一天的讀取共用（讀完 5 分鐘內另一邊直接用），所以兩份的列一模一樣；
  某一邊晚了超過 5 分鐘（例如它的試算表出錯、10 分鐘後重試）才會自己再讀一次 Discord。
  某一邊的試算表**一直**寫不進去時，它每 10 分鐘重試一次、每次都會再讀那天——上限是「兩邊各讀各的」，和主匯出原本的重試一樣（免費）。
- **一邊出錯不影響另一邊**：私人那份寫不進去（例如沒分享給服務帳號），阿瓦隆百科那份照寫；反過來也一樣。各自 10 分鐘後重試、自己補齊。
- 自動停用的情況（狀態頁 `readingCopy.enabled=false`，server log `[chat-export:reading-copy] disabled (…)`）：
  - `CHAT_EXPORT_READING_COPY_SHEET_ID=off`；
  - `CHAT_EXPORT_SHEET_ID=off`（「不要任何試算表」：主匯出關掉時，副本也不寫）；

### 「聊天紀錄」分頁的欄位

| 日期 | 時間（+08） | 頻道 | 來源 | 發言者代號 | 內容 |
|---|---|---|---|---|---|
| 2026-10-12 | 2026-10-12 21:33 | 阿瓦隆同步 | LINE | 成員3 | 排行怎麼沒更新 |
| 2026-10-12 | 2026-10-12 21:35 | 一般聊天 | Discord | 成員7 | 應該是快取 ⏎ 明天再看〔附件 1〕 |
| 2026-10-12 | 2026-10-12 22:10 | 牌譜紀錄與覆盤／1012一般場3 | Discord | 成員2 | 已修正格式 |

- **日期**＝那則訊息所在的那一天（台灣時間 00:00～24:00）；**時間**＝台灣時間到分鐘。
- **頻道**：一般頻道寫頻道名；論壇貼文寫「論壇名／貼文標題」。
- **來源**：`Discord`、`LINE`、`網站`（網站大廳）；舊版同步格式（`CHAT_MIRROR_USE_LEGACY_FORMAT=true`）分不出來源，記為 `同步`。
- **發言者代號**：同一天裡同一個人同一個代號，**天與天之間不對應**（每天從成員1 重新編號；試算表預設是公開的阿瓦隆百科那份，
  跨天一致的代號會讓人把一個人好幾天的發言串起來，比較容易認出是誰）；LINE 和 Discord 上同名的人算兩個人。
- **內容**：換行寫成「 ⏎ 」；`@某人` → `@成員N`、`@身分組` → `@某身分組`、`#頻道` → `#頻道名`；附件寫成「〔附件 N〕」；超過 4000 字截斷。
  伺服器圖片轉傳的連結（`…/media/relay/…`，Discord 圖片轉到 LINE 用的）寫成「〔圖片連結〕」，不會出現在試算表裡
  （沒有 `https://`、中間夾 `/./`、全形字母或 `%2F` 的寫法也一樣，含這種連結的整個詞都換掉）。
  以 RAW 寫入，所以有人打 `=SUM(...)` 也只是文字，不會變成公式。
- 匿名的是「誰說的」：內文裡提到的名字（例如「某某昨天那局」）不會被改掉。AI 管理員回報時不點名。
- 分頁不存在時，bot 會自動建立「聊天紀錄」和「匯出紀錄」兩個分頁並寫好標題列（凍結第 1 列）；其他分頁不會被動到。

### 「匯出紀錄」分頁的欄位

| 日期 | 狀態 | 列數 | 頻道數 | 時間（+08） | 執行代號 |
|---|---|---|---|---|---|
| 2026-10-12 | 進行中 | 0 | 0 | 2026-10-13T04:30:41+08:00 | 3f9a1c07 |
| 2026-10-12 | 完成 | 356 | 8 | 2026-10-13T04:31:10+08:00 | 3f9a1c07 |
| 2026-10-13 | 清理中 | 0 | 0 | 2026-10-13T04:31:12+08:00 | 3f9a1c07 |
| 2026-10-13 | 清理結束 | 0 | 0 | 2026-10-13T04:31:14+08:00 | 3f9a1c07 |

- **完成**＝那一天的「聊天紀錄」已經完整寫好（`列數` 就是那天的列數，0 表示那天沒有聊天；`頻道數` 含論壇貼文）。**只有「完成」的日子才算數**。
- **進行中**＝某一台伺服器正在寫那一天（執行代號是那個程序隨機產生的 8 碼，重啟就換新的，沒有其他意思；
  閱讀副本的執行代號前面多了 `copy-`，副本只把這種「完成」算數，見「閱讀副本」一節）。
- **清理中／清理結束**＝某一台正在刪列（刪 7 天以前的列，或刪某天寫到一半留下的列）；日期是刪列的那天，不是匯出的日子。
  Google 刪列是照「第幾列」刪的：兩台同時刪，後刪的那台會刪到往上移的列——也就是保留中、已經「完成」的日子，而且不會有任何警告。
  所以**同一時間只讓一台刪**：還沒「清理結束」、10 分鐘內最早的那列「清理中」是誰的，就由那台刪（拿到後 3 分鐘內沒刪完就放棄、下次再來）；
  另一台這次不刪，寫一列「清理結束」放掉自己那列，10 分鐘後再看。這些列跟著日期，7 天後一起被刪掉。
  刪列的請求斷線、逾時或 Google 回 5xx（**刪了沒有不確定**，晚一點才生效也有可能）時，那台**不寫**「清理結束」，鎖放著 10 分鐘自然失效，
  免得另一台在這段時間照舊的列號去刪、刪到別天。
- 這個分頁是程式在用的，請不要手動改（例如刪掉某天的「完成」，那天的聊天列會在下次被當成沒寫完而刪掉重寫）。
  整個分頁刪掉不會壞：下一次要寫新的一天時 bot 會重建它；下次重啟（部署）時，最近 7 天裡沒有「完成」的日子會整天刪掉重寫一次（不會重複）。

### 什麼時候跑、會不會重複

- **重啟後補齊**：伺服器一啟動（每次部署都會），Discord 一連上——不管幾點——就檢查最近 7 個完整的日子（昨天往前 7 天），
  「匯出紀錄」裡沒有「完成」的，從最舊的開始一天一天寫。所以部署後幾分鐘內，試算表就有最近 7 天。
- **每天**：台灣時間 04:30 起匯出前一天 00:00～24:00。沒成功的話每 10 分鐘再試；那一天在 7 天內都會繼續補，過了午夜也一樣。
- **同一天只會有一份完整的資料**，重啟或兩台伺服器同時在跑（Render 部署交接時新舊兩台會重疊一陣子）都一樣：
  1. 「匯出紀錄」已經有那天的「完成」→ 不再讀、不再寫。
  2. 開始前先寫一列「進行中」再讀回來：最早的那列（30 分鐘內）是誰的，就由那台寫，另一台跳過那天、先做別天（狀態 `claimed-elsewhere`，10 分鐘後再看）。
     寫的那台重試時（每 10 分鐘一次），自己的「進行中」超過 15 分鐘就補寫一列新的（所以大約每 20 分鐘一列），只要它還活著，別台就不會插手。
     「進行中」的時間是真的開始處理那天的時間：補齊 7 天要讀很久時，後面的日子不會帶著一開始的時間、一寫上去就被別台當成過期。
  3. 寫之前，那天在「聊天紀錄」裡如果已經有列（上次寫到一半：程序被關掉、Google 出錯），先拿「清理」鎖全部刪掉，再整天寫入，最後寫「完成」。
     鎖在另一台手上時，那天先不寫（`claimed-elsewhere`），10 分鐘後再來。
  4. 寫的那台中途被關掉：它的「進行中」30 分鐘後失效，下一台接手，照第 3 步把半天的列刪掉重寫。
- 一次送 500 列。寫到一半失敗（例如 Google 暫時出錯）會先試著把那天已寫入的列刪掉，整輪停 10 分鐘後再從那天重寫。
- 有頻道讀不到（Discord 暫時出問題）：一部分讀不到會 10 分鐘後再讀一次，第二次就把讀得到的寫進去；
  **一個頻道都讀不到**時不會當成「那天沒聊天」，整輪停 10 分鐘再讀。一天真的都沒有聊天，只寫一列「完成」（列數 0）。
- **刪掉 7 天以前的列**（兩個分頁都是；保留昨天往前 7 天）：伺服器啟動後一次，之後每天 04:30 起、有一天超出 7 天時一次；
  日期欄不是日期的列（標題、有人手寫的備註）不會被刪。有東西要刪才拿「清理」鎖；鎖在另一台手上（多半是它正在刪同樣的列）或 Google 出錯時，
  10 分鐘後再刪一次，不用等到隔天。
- 刪舊列**只需要試算表**：Discord 斷線、bot token 失效時照樣刪（不讀 Discord、不寫新的一天）；
  匯出被停掉（`CHAT_EXPORT_ALLOW_PUBLIC_SHEET=0` 或 `CHAT_EXPORT_ENABLED=false`）時也照樣刪舊的那份——只刪、不建分頁、不寫聊天列
  （見上方「要停或改回私人那份」）。所以只要服務帳號還能寫那份試算表，裡面就不會留超過 7 天（Edward：「最多保留近一週」）。
- 匯出只處理最近 7 天；Discord 或 Google 斷了超過一週，更早的日子就不會補。

- LINE 群裡打的 `/意見 …` 原文照常同步到 Discord 同步頻道與網站大廳（Edward 第 5 點：要同步）。
- 旗標：`FEEDBACK_COMMAND_ENABLED`（預設開；`false/0/no/off` 關）。


## `/api/bots/status`（公開，只有數字）

```json
"feedback": {
  "commandEnabled": true,
  "weeks": [ { "week": "2026-W42", "line": { "排行": 3, "問題": 1, "...": 0 }, "discord": { "機器人": 2, "...": 0 } } ],
  "opinions": { "line": 1, "discord": 0 }
},
"chatExport": {
  "enabled": true, "sheetConfigured": true, "publicSheet": true,
  "lastRun": { "day": "2026-10-12", "at": "2026-10-13T02:03:40.000Z", "messages": 356, "channels": 8, "threads": 3, "truncated": 0, "outcome": "written" },
  "catchUp": { "startedAt": "2026-10-13T02:01:05.000Z", "from": "2026-10-06", "to": "2026-10-12", "exported": 7, "skipped": 0, "failed": 0, "pending": 0, "expired": 0 },
  "readingCopy": {
    "enabled": true, "sheetConfigured": true,
    "lastRun": { "day": "2026-10-12", "at": "2026-10-13T02:03:41.000Z", "messages": 356, "channels": 8, "threads": 3, "truncated": 0, "outcome": "written" },
    "catchUp": { "startedAt": "2026-10-13T02:01:05.000Z", "from": "2026-10-06", "to": "2026-10-12", "exported": 7, "skipped": 0, "failed": 0, "pending": 0, "expired": 0 }
  }
}
```

- `chatExport.enabled`：`CHAT_EXPORT_ENABLED`（預設開）。`sheetConfigured`：有試算表 id（沒被拒絕），而且服務帳號 JSON 真的讀得懂。
  `publicSheet`：正在寫阿瓦隆百科那份（預設，且 `sheetConfigured` 為 `true`；`false` 表示 `CHAT_EXPORT_SHEET_ID`——或舊名 `COMMUNITY_DIGEST_SHEET_ID`——指定了別份、
  那份被 `CHAT_EXPORT_ALLOW_PUBLIC_SHEET=0` 拒絕，或根本沒設好服務帳號 JSON）。
- `lastRun`（記憶體，重啟後是 `null`）：最近處理的那一天。`day` 日期、`at` 執行時間、`messages` 寫了幾列、`channels` 有幾個頻道（含論壇貼文）有訊息、
  `threads` 其中幾篇是論壇貼文、`truncated` 讀取上限被觸發幾次（> 0 表示那天可能不完整）、`outcome`：

  | outcome | 意思 |
  |---|---|
  | `written` | 那天寫好了（「匯出紀錄」有「完成」） |
  | `already-exported` | 那天早就寫好（「匯出紀錄」已有「完成」，例如重啟後、或另一台伺服器寫的） |
  | `empty` | 那天沒有可以匯出的聊天（只寫「完成」，列數 0） |
  | `claimed-elsewhere` | 另一台伺服器正在寫那天；或那天有寫到一半的列要先刪、而另一台正拿著「清理」鎖（部署交接時會出現），10 分鐘後再看 |
  | `not-configured` | 沒有試算表 id 或服務帳號 JSON，或 id 是阿瓦隆百科那份但設了 `CHAT_EXPORT_ALLOW_PUBLIC_SHEET=0`（被拒絕） |
  | `sheet-error` | Google Sheets 呼叫失敗（多半是試算表沒分享給服務帳號），整輪停 10 分鐘再試 |
  | `tab-conflict` | 試算表裡已經有同名但標題列不一樣的「聊天紀錄」或「匯出紀錄」分頁，不是 bot 的，不碰；改名或刪掉那個分頁後自動恢復 |
  | `read-error` | 有頻道讀不到：一部分 → 那天 10 分鐘後再讀一次；全部（或 Discord 伺服器還沒載入）→ 整輪停 10 分鐘再讀 |
  | `error` | 未預期的錯誤（server log 有原因代碼），10 分鐘後再試 |

- `catchUp`（記憶體，Discord 連上且試算表設定好後才有）：這次啟動後補齊的那 7 天，依每天最新的結果計數：
  `exported` 這台寫的（含沒聊天的日子）、`skipped` 早就寫好或另一台正在寫、`failed` 最近一次失敗（還在 7 天內，會再試）、`pending` 還沒輪到、
  `expired` 還沒寫好就已經超出最近 7 天的日子（不會再試；伺服器連續跑好幾天、那幾天又一直失敗才會出現）。五個加起來是 7。
- `readingCopy`：閱讀副本自己的狀態（沒有試算表 id，只有布林、日期、數字和結果代碼）。`enabled`：`CHAT_EXPORT_ENABLED` 開著、而且副本沒被關掉或自動停用
  （見「閱讀副本」一節）；`sheetConfigured`：副本有試算表 id、服務帳號 JSON 讀得懂；`lastRun`、`catchUp` 的意思和上面一樣，只是指私人那份。
  `lastRun.messages` 應該和主匯出同一天的一樣；`outcome=sheet-error` 多半是那份沒分享給服務帳號（編輯者）。
