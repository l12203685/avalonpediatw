  而且它的 id 就寫在這個公開 repo 裡（戰績快取每天從它重算）——等於**任何人都能打開**。

## 匯出的內容

### 讀哪些訊息

- Discord 伺服器裡**所有人（@everyone）都看得到**的文字頻道和公告頻道。
- **論壇**（@everyone 看得到、bot 讀得到的論壇頻道，例如 #牌譜紀錄與覆盤）：那一天在各貼文（討論串）裡發的訊息——
  貼文本身（開頭那則）和底下的回覆都收，進行中與已封存的貼文都讀。
  - **#牌譜紀錄與覆盤**（`1132683080134578276`）例外：每篇貼文開頭那則是牌譜本身（是資料，不是意見），**不收**；
    底下的回覆照收，包括玩家回應機器人「格式看不懂」那則回覆的話。機器人自己的格式回覆照一般規則不收。
  - 封存的貼文從最近封存的往回讀，讀到「在那一天開始前就封存」的就停（那種貼文裡不可能有那天的訊息）。
  - 一般文字頻道底下開的討論串目前不讀（只讀論壇的貼文）。
- **LINE↔Discord 同步頻道**（`LOBBY_MIRROR_DISCORD_CHANNEL_ID`，就算 @everyone 看不到也讀；除非列在 `CHAT_EXPORT_EXCLUDE_CHANNEL_IDS`）。LINE 群的發言是 bot 轉貼進來的，
  格式 `[1005 21:35][LINE][名字] 內容`；匯出時當成 LINE 的發言，名字換成代號。網站大廳轉貼的 `[…][AP][名字] …` 也一樣（來源記為「網站」）。
- 不收：bot 自己的其他貼文（每週排行、指令回覆、牌譜格式回覆、`📮 意見` 轉貼）、其他 bot、webhook、系統訊息、
  指令（`/戰績`、`/意見`…，包含 LINE 那邊打的）、只有圖片沒有文字的訊息（只算數量）。
- 一定不讀：管理員頻道「大劍管理員」（不管 `/意見` 轉貼到哪裡、就算 @everyone 看得到），以及 `FEEDBACK_DISCORD_CHANNEL_ID` 另外指定的 `/意見` 頻道（是論壇裡的討論串也一樣）；
  私人頻道與私人論壇本來就不在預設名單裡。
- 可調（逗號或空白分隔的 id）：
  - `CHAT_EXPORT_EXTRA_SOURCE_IDS`：**另外加讀**這些頻道或論壇，預設名單照讀。@everyone 看不到的也會讀
    （寫在阿瓦隆百科那份時，等於把那個頻道公開）。例如 #牌譜紀錄與覆盤 若對 @everyone 隱藏，就填 `1132683080134578276`。
  - `CHAT_EXPORT_SOURCE_CHANNEL_IDS`：**取代**預設名單，只讀這些頻道或論壇（同步頻道與 `CHAT_EXPORT_EXTRA_SOURCE_IDS` 仍會加上）。
    只填一個 id 就只讀那一個，其他公開頻道與論壇全部不讀——只是想多讀一個的話請用上一個變數。
  - `CHAT_EXPORT_EXCLUDE_CHANNEL_IDS`：不讀這些頻道、論壇或**單一貼文**；排除永遠優先。
  - 兩個「讀」的清單只收文字頻道、公告頻道或論壇。填單一貼文（討論串）、不存在或 bot 讀不到的 id 會被略過，
    server log 記「N id(s) … ignored」（只有數量），狀態頁不變。單一貼文只能用在 `CHAT_EXPORT_EXCLUDE_CHANNEL_IDS`。
- 如果伺服器把所有頻道都對 @everyone 關掉、只開給「成員」之類的身分組，預設規則會找不到公開頻道、只讀同步頻道；
  server log 會提醒，這時請把要讀的頻道填進 `CHAT_EXPORT_EXTRA_SOURCE_IDS`。
- 每匯出一天的讀取量有上限，超過時照樣寫入讀到的部分、並在狀態頁 `lastRun.truncated` 與 log 記數量（不會悄悄漏掉）：
  每個頻道 5,000 則、每篇貼文 1,000 則、每個論壇往回列 1,000 篇封存貼文、最多讀 300 篇貼文。
  上限是**每一天各自**算的（重啟後補 7 天就是 7 次，各自最多 300 篇），不會因為前面幾天讀很多，就把後面的日子截斷後寫成「完成」。

### 「聊天紀錄」分頁的欄位

| 日期 | 時間（+08） | 頻道 | 來源 | 發言者代號 | 內容 |
|---|---|---|---|---|---|
| 2026-10-12 | 2026-10-12 21:33 | 阿瓦隆同步 | LINE | 成員3 | 排行怎麼沒更新 |
| 2026-10-12 | 2026-10-12 21:35 | 一般聊天 | Discord | 成員7 | 應該是快取 ⏎ 明天再看〔附件 1〕 |
| 2026-10-12 | 2026-10-12 22:10 | 牌譜紀錄與覆盤／1012一般場3 | Discord | 成員2 | 已修正格式 |

- **日期**＝那則訊息所在的那一天（台灣時間 00:00～24:00）；**時間**＝台灣時間到分鐘。
- **頻道**：一般頻道寫頻道名；論壇貼文寫「論壇名／貼文標題」。
- **來源**：`Discord`、`LINE`、`網站`（網站大廳）；舊版同步格式（`CHAT_MIRROR_USE_LEGACY_FORMAT=true`）分不出來源，記為 `同步`。
- **發言者代號**：同一天裡同一個人同一個代號，**天與天之間不對應**（每天從成員1 重新編號；試算表可能是公開的那份，
  跨天一致的代號會讓人把一個人好幾天的發言串起來，比較容易認出是誰）；LINE 和 Discord 上同名的人算兩個人。
- **內容**：換行寫成「 ⏎ 」；`@某人` → `@成員N`、`@身分組` → `@某身分組`、`#頻道` → `#頻道名`；附件寫成「〔附件 N〕」；超過 4000 字截斷。
  伺服器圖片轉傳的連結（`…/media/relay/…`，Discord 圖片轉到 LINE 用的）寫成「〔圖片連結〕」，不會出現在試算表裡。
  以 RAW 寫入，所以有人打 `=SUM(...)` 也只是文字，不會變成公式。
- 匿名的是「誰說的」：內文裡提到的名字（例如「某某昨天那局」）不會被改掉。AI 管理員回報時不點名。
- 分頁不存在時，bot 會自動建立「聊天紀錄」和「匯出紀錄」兩個分頁並寫好標題列（凍結第 1 列）；其他分頁不會被動到。

### 「匯出紀錄」分頁的欄位

| 日期 | 狀態 | 列數 | 頻道數 | 時間（+08） | 執行代號 |
|---|---|---|---|---|---|
| 2026-10-12 | 進行中 | 0 | 0 | 2026-10-13T04:30:41+08:00 | 3f9a1c07 |
| 2026-10-12 | 完成 | 356 | 8 | 2026-10-13T04:31:10+08:00 | 3f9a1c07 |
| 2026-10-13 | 清理中 | 0 | 0 | 2026-10-13T04:31:12+08:00 | 3f9a1c07 |
| 2026-10-13 | 清理結束 | 0 | 0 | 2026-10-13T04:31:14+08:00 | 3f9a1c07 |

- **完成**＝那一天的「聊天紀錄」已經完整寫好（`列數` 就是那天的列數，0 表示那天沒有聊天；`頻道數` 含論壇貼文）。**只有「完成」的日子才算數**。
- **進行中**＝某一台伺服器正在寫那一天（執行代號是那個程序隨機產生的 8 碼，重啟就換新的，沒有其他意思）。
- **清理中／清理結束**＝某一台正在刪列（刪 7 天以前的列，或刪某天寫到一半留下的列）；日期是刪列的那天，不是匯出的日子。
  Google 刪列是照「第幾列」刪的：兩台同時刪，後刪的那台會刪到往上移的列——也就是保留中、已經「完成」的日子，而且不會有任何警告。
  所以**同一時間只讓一台刪**：還沒「清理結束」、10 分鐘內最早的那列「清理中」是誰的，就由那台刪（拿到後 3 分鐘內沒刪完就放棄、下次再來）；
  另一台這次不刪，寫一列「清理結束」放掉自己那列，10 分鐘後再看。這些列跟著日期，7 天後一起被刪掉。
- 這個分頁是程式在用的，請不要手動改（例如刪掉某天的「完成」，那天的聊天列會在下次被當成沒寫完而刪掉重寫）。
  整個分頁刪掉不會壞：下一次要寫新的一天時 bot 會重建它；下次重啟（部署）時，最近 7 天裡沒有「完成」的日子會整天刪掉重寫一次（不會重複）。

### 什麼時候跑、會不會重複

- **重啟後補齊**：伺服器一啟動（每次部署都會），Discord 一連上——不管幾點——就檢查最近 7 個完整的日子（昨天往前 7 天），
  「匯出紀錄」裡沒有「完成」的，從最舊的開始一天一天寫。所以部署後幾分鐘內，試算表就有最近 7 天。
- **每天**：台灣時間 04:30 起匯出前一天 00:00～24:00。沒成功的話每 10 分鐘再試；那一天在 7 天內都會繼續補，過了午夜也一樣。
- **同一天只會有一份完整的資料**，重啟或兩台伺服器同時在跑（Render 部署交接時新舊兩台會重疊一陣子）都一樣：
  1. 「匯出紀錄」已經有那天的「完成」→ 不再讀、不再寫。
  2. 開始前先寫一列「進行中」再讀回來：最早的那列（30 分鐘內）是誰的，就由那台寫，另一台跳過那天、先做別天（狀態 `claimed-elsewhere`，10 分鐘後再看）。
     寫的那台重試時（每 10 分鐘一次），自己的「進行中」超過 15 分鐘就補寫一列新的（所以大約每 20 分鐘一列），只要它還活著，別台就不會插手。
     「進行中」的時間是真的開始處理那天的時間：補齊 7 天要讀很久時，後面的日子不會帶著一開始的時間、一寫上去就被別台當成過期。
  3. 寫之前，那天在「聊天紀錄」裡如果已經有列（上次寫到一半：程序被關掉、Google 出錯），先拿「清理」鎖全部刪掉，再整天寫入，最後寫「完成」。
     鎖在另一台手上時，那天先不寫（`claimed-elsewhere`），10 分鐘後再來。
  4. 寫的那台中途被關掉：它的「進行中」30 分鐘後失效，下一台接手，照第 3 步把半天的列刪掉重寫。
- 一次送 500 列。寫到一半失敗（例如 Google 暫時出錯）會先試著把那天已寫入的列刪掉，整輪停 10 分鐘後再從那天重寫。
- 有頻道讀不到（Discord 暫時出問題）：一部分讀不到會 10 分鐘後再讀一次，第二次就把讀得到的寫進去；
  **一個頻道都讀不到**時不會當成「那天沒聊天」，整輪停 10 分鐘再讀。一天真的都沒有聊天，只寫一列「完成」（列數 0）。
- 每一輪做完會**刪掉 7 天以前的列**（兩個分頁都是；保留昨天往前 7 天）；日期欄不是日期的列（標題、有人手寫的備註）不會被刪。
  有東西要刪才拿「清理」鎖；鎖在另一台手上（多半是它正在刪同樣的列）或 Google 出錯時，10 分鐘後再刪一次，不用等到隔天。
- 匯出只處理最近 7 天；Discord 或 Google 斷了超過一週，更早的日子就不會補。

## `/api/bots/status`（公開，只有數字）

```json
"feedback": {
  "commandEnabled": true,
  "weeks": [ { "week": "2026-W42", "line": { "排行": 3, "問題": 1, "...": 0 }, "discord": { "機器人": 2, "...": 0 } } ],
  "opinions": { "line": 1, "discord": 0 }
},
"chatExport": {
  "enabled": true, "sheetConfigured": true, "publicSheet": false,
  "lastRun": { "day": "2026-10-12", "at": "2026-10-13T02:03:40.000Z", "messages": 356, "channels": 8, "threads": 3, "truncated": 0, "outcome": "written" },
  "catchUp": { "startedAt": "2026-10-13T02:01:05.000Z", "from": "2026-10-06", "to": "2026-10-12", "exported": 7, "skipped": 0, "failed": 0, "pending": 0, "expired": 0 }
}
```

- `chatExport.enabled`：`CHAT_EXPORT_ENABLED`（預設開）。`sheetConfigured`：有試算表 id（沒被拒絕），而且服務帳號 JSON 真的讀得懂。
  `publicSheet`：正在寫阿瓦隆百科那份（`CHAT_EXPORT_ALLOW_PUBLIC_SHEET=1`）。
- `lastRun`（記憶體，重啟後是 `null`）：最近處理的那一天。`day` 日期、`at` 執行時間、`messages` 寫了幾列、`channels` 有幾個頻道（含論壇貼文）有訊息、
  `threads` 其中幾篇是論壇貼文、`truncated` 讀取上限被觸發幾次（> 0 表示那天可能不完整）、`outcome`：

  | outcome | 意思 |
  |---|---|
  | `written` | 那天寫好了（「匯出紀錄」有「完成」） |
  | `already-exported` | 那天早就寫好（「匯出紀錄」已有「完成」，例如重啟後、或另一台伺服器寫的） |
  | `empty` | 那天沒有可以匯出的聊天（只寫「完成」，列數 0） |
  | `claimed-elsewhere` | 另一台伺服器正在寫那天；或那天有寫到一半的列要先刪、而另一台正拿著「清理」鎖（部署交接時會出現），10 分鐘後再看 |
  | `not-configured` | 沒有試算表 id 或服務帳號 JSON，或 id 是阿瓦隆百科那份但沒開 `CHAT_EXPORT_ALLOW_PUBLIC_SHEET`（被拒絕） |
  | `sheet-error` | Google Sheets 呼叫失敗（多半是試算表沒分享給服務帳號），整輪停 10 分鐘再試 |
  | `tab-conflict` | 試算表裡已經有同名但標題列不一樣的「聊天紀錄」或「匯出紀錄」分頁，不是 bot 的，不碰；改名或刪掉那個分頁後自動恢復 |
  | `read-error` | 有頻道讀不到：一部分 → 那天 10 分鐘後再讀一次；全部 → 整輪停 10 分鐘再讀 |
  | `error` | 未預期的錯誤（server log 有原因代碼），10 分鐘後再試 |

- `catchUp`（記憶體，Discord 連上且試算表設定好後才有）：這次啟動後補齊的那 7 天，依每天最新的結果計數：
  `exported` 這台寫的（含沒聊天的日子）、`skipped` 早就寫好或另一台正在寫、`failed` 最近一次失敗（還在 7 天內，會再試）、`pending` 還沒輪到、
  `expired` 還沒寫好就已經超出最近 7 天的日子（不會再試；伺服器連續跑好幾天、那幾天又一直失敗才會出現）。五個加起來是 7。
