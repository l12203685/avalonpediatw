# 牌譜總庫（第 1 步）

站長 2026-11-17：「你有自己獨立的牌譜資料庫嗎 (從各個地方蒐集而來的) 因為可能會重複或是登錄錯誤等等的 我希望你自己有建好自己的牌譜資料庫」。

- **總庫**：`packages/server/game_db.json`。每一局一筆：總庫編號、類型（實戰／模擬／百科AI）、日期、分類、來源清單、牌譜（配置、每次提議的隊伍與投票記號、任務、湖、刺殺、結果）、逐條檢查結果。
- **產生**：`packages/server/game_db.py`（純 Python 標準庫）。每天跟著 `refresh-analysis-cache` 重算，排在 `games_cache.json`、`records_cache.json` 之後。失敗時保留舊檔，不擋快取推送。
- **檢查報告**：`docs/data/game_db_report.md`，跟總庫一起自動產生。
- **隱私**：沒有玩家名字、標題或文字，只有座位、牌譜、編號與日期。
- **這一步沒有改**：網站、統計、機器人照舊讀原本的三個檔。第 2 步才改成從總庫產生，計畫在報告最後。

## 來源怎麼進總庫

| 來源 | 原本進哪個檔 | 總庫裡的來源名 |
|---|---|---|
| 試算表「牌譜」分頁（實戰） | `games_cache.json`（id = 流水號）→ `records_cache.json` 的 `S<流水號>` | `sheet` |
| 試算表「Discord匯入」分頁（從 Discord 貼文抄進試算表的局） | `games_cache.json`（id = `D<hash>`） | `dc_import` |
| Discord 論壇 #牌譜紀錄與覆盤（一篇一局） | `records_cache.json`（id = 貼文 id；讀不懂的 `game` 是空的） | `discord` |
| 試算表「模擬瓦」分頁（模擬） | `records_cache.json` 的 `M<流水號>` | `sim_sheet` |
| ProAvalon 匿名匯出（2018–2022，外部） | 只轉「10 人、梅派刺娜德奧、有湖中」的局：`proavalon_import.py` → `proavalon_games.json`（id `P<_id>`）。其他局只存在站長的私人 repo | `proavalon`（`external: true`）。**2026-11-18 起預設不進總庫**（見下面第 6 點） |
| 試算表「牌譜」分頁的快照 `sheets_cache.json` | `sim_bank.json`（模擬瓦／Threads 題庫）從這裡建 | 只檢查涵蓋，不另算一個來源 |

- **合併**：配置、每次提議的隊伍、每局任務全部相同，就是同一局（`generate_cache.record_fingerprint`，跟牌譜紀錄頁用的一樣）。模擬永遠不跟實戰合併。
- **內容取自哪個來源**：優先序是試算表 → Discord 貼文 → Discord匯入 → 模擬瓦，也就是統計用的那一份。
- **總庫編號**：用網站牌譜紀錄頁的編號。有 Discord 貼文就用貼文 id，沒有就依序用 `S<流水號>`、`D<hash>`、`M<流水號>`。紀錄改正之後編號不變。

## 檢查規則

規則的完整清單、每條的局數，以及要人看的局，都在報告裡。

**錯**：牌譜跟遊戲規則矛盾，例如：
- 配置不是 6 個不同座位；隊伍人數不是 3、4、4、5、5；同一隊重複座位。
- 任務張數跟隊伍人數不同；失敗張數比隊上的紅方多（依配置）。
- 分出勝負後還有局，或沒分出勝負就結束；第 4 局要 2 張失敗才算失敗。
- 結果欄跟任務、刺殺對不上（刺中梅林＝三藍死）。
- 湖不合規則：同一人、斷鏈、驗過的人又被驗、不在第 2～4 局後。

這些規則沿用 `discord_records_import.py` 匯入時檢查的同一套。

**提醒**：多半是紀錄不完整，例如：
- 投票張數跟提議過不過對不上：出任務的提議贊成不到 6 張，或過半卻沒出任務。多半是漏記了場外白或場內黑；這跟網站「決定性票」排除的「紀錄有錯」是同一條。
- 投票記號跟隊伍對不上；三藍沒有刺殺目標。
- 同一來源登錄兩次；兩個來源記的不一樣；同一天、同配置卻是不同牌譜（疑似重複）。

**參考**：有它不算錯，例如：
- 試算表 note 標了 review／badGame。
- 湖的宣告沒記；沒有日期。
- 推不出隊長輪替：用的是 `mistakes.ts` 的 `deriveLeaderSeats`，隊長多半會派自己。

模擬瓦的局常常只打到一半，所以不檢查跟「整局打完」有關的規則。

## 站長 2026-11-18：五個鐵好之後的任務是定的

站長（S1982、S1810、S2019 的裁定）：「有五個鐵好了 你要不要先重新確認一下 有五鐵好的情況 幫我補上這些 再開其他有問題的」。紅方兩紅之後，成功的任務加上湖的結果等等讓五個人確定是好人（鐵好），後面的任務只會是這五人出、全部成功，直接進刺殺，紀錄常常就停在那裡。

`game_db.py` 的 `complete_iron_good` 照這條補完，**只在推得很死的時候**：

- **鐵好**（`iron_good`）：把 4 個紅方放進 10 個座位的所有排法裡，留下跟公開紀錄不矛盾的，每一種都是好人的座位才算。只用三條硬規則：出了 f 張失敗的隊上至少 f 個紅方；紅方已經兩紅之後，紅方出任務一定出失敗（再一局失敗就贏），所以要 1 張失敗的局成功＝隊上沒有紅方、第 4 局成功＝隊上最多 1 個紅方；好人持湖說真話（宣告 o＝被驗的是好人、x＝紅方，`?` 或沒記不算）。投票和誰派誰都不用（那是行為，不是證明）。
- **補完的條件**：紀錄唯一的錯是「沒有一方拿到 3 局」（另外容許停在最後一局之後的湖）；剛好五個鐵好；後面要補的局都是 5 人局（六個鐵好時派誰不確定，不補）；原紀錄的結果不是三紅，有刺殺目標時結果跟目標對得上；補完後重新檢查沒有錯。
- **怎麼補**：後面每一局一次提議、隊伍是這五人、`ooooo`；刺殺照原紀錄（三藍死／活依配置），沒有刺殺的照樣標「三藍卻沒有刺殺目標」。總庫那一局加 `completed: {kind: five_iron_good, rounds, team, facts}` 和一條參考 `IRON_GOOD`，`fp` 仍是來源原本的紀錄（合併照來源）。報告列「五個鐵好：補完的局」與每局的根據。

## 站長 2026-11-20：日期不同的都以試算表為準

站長：「日期不同的都以試算表為準 因為discord 上發文的日期不一定是遊戲日期 他們標題也都沒有照預定格式寫 所以搜尋很困難」。

- **規則**：同一局試算表（「牌譜」或「模擬瓦」分頁）跟 Discord 都有、日期不同時，這局的日期一律用試算表的。Discord 的日期是標題開頭的 MMDD（標題常常沒照格式寫），沒有就是發文日，不一定是打的那天。「Discord匯入」分頁的日期是從 Discord 貼文抄的，不算試算表的日期。
- **總庫**（`game_db.py` 的 `SHEET_SOURCES`、`game_date`）：合併後的日期先取試算表來源的（記錯被併掉的試算表那筆也算，那是同一局），沒有才取其他來源的。試算表跟 Discord 只差日期，不再標「不同來源記的不一樣」（`CONFLICT`）；結果、刺殺、湖、投票、線上／面對面不一樣照舊標。兩個都不是試算表的來源（例如 Discord 貼文跟 Discord匯入）日期不同，還是標。
- **網站牌譜紀錄清單**（`records_merge.merge_posts`）：試算表也有的 DC 貼文（`src: "dc+sheet"`）的 `date` 用試算表的日期，貼文自己的日期留在 `postDate`（只記來源；下次重新合併從它開始）。日期篩選、排序、搜尋都看 `date`。只在 DC 的貼文照舊（標題的 MMDD，沒有就發文日）。這一晚沒讀到試算表（`games_cache.json` 不在）時，沿用上一版的合併結果。
- **跟著總庫的地方**：主控台的問題牌譜（`console_export.py`）只差日期的局不再列在「來源不一致」；「疑似同一局」（同一天、同配置）用總庫的日期。`sim_bank.json` 沒有日期；戰績分析的 `games_cache.json` 本來就是試算表那筆優先（同指紋的 Discord匯入列不算）。
- **還沒改的**：試算表有錯的局併到 Discord 更正版（`SUPERSEDED`）仍要求兩邊同一天；2026-11-20 的資料試過不看日期，也沒有多併到任何一局。
- **2026-11-20 的資料**：網站清單 13 篇 DC 貼文的日期改成試算表的；總庫 `CONFLICT` 18 → 5（13 筆只差日期的不見了）。總庫每局的日期本來就先取試算表（優先序第一），所以總庫的日期沒有變。
