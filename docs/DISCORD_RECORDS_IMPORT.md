# Discord 牌譜自動收錄、格式回覆與每週修正清單

每天凌晨 3:17（台灣時間），機器人會讀 Discord 論壇 **#牌譜紀錄與覆盤** 的貼文（一篇貼文 = 一局），把讀得懂的牌譜收進戰績試算表的「Discord匯入」分頁。3:47 戰績分析快取更新時，「牌譜」和「Discord匯入」會一起算進去。

不會重複收錄：已經在「牌譜」分頁的局、標了「已收錄」的貼文都會跳過；標「模擬」的貼文不收錄。

程式：`packages/server/discord_records_import.py`；排程：`.github/workflows/import-discord-records.yml`。

## 機器人在貼文底下回覆什麼

牌譜格式有問題、沒辦法自動收錄時，機器人會在那篇貼文的討論串回一則 **「🤖 牌譜格式檢查」**，內容包括：

- 第幾行有問題、那一行寫了什麼、原因
- 格式提示
- 「修好後不用做別的，下次排程會自動重新讀取」

規則：

- 只回最近 14 天發的貼文，**每篇只回一次**（回覆被刪掉也不會再回）。
- 每次最多回 20 篇，其餘的下一次再回。
- 不會 @ 任何人；引用的那一行裡如果有連結或 @，只會顯示成文字。
- 以下貼文不回：標「已收錄」或「模擬」、第一則訊息被刪掉或是空白、純討論的貼文（沒有牌譜、沒有結果標籤、也沒有 6 碼配置）。

## 每週「牌譜修正」清單

每週一凌晨，機器人會在 Discord 文字頻道 **「牌譜修正」** 發一份清單，第一行是「🤖 牌譜修正清單 2026-W42（2026/10/12 這週）」這樣的標題。週一的排程如果失敗或沒跑，週二、週三凌晨會補發。

- 列出**最近 30 天發文**、因為格式問題還沒收進戰績統計的牌譜（跟上面會收到回覆的是同一批規則），依牌譜日期排列。
- 每篇一行：日期、當天第幾場、原因、第幾行、貼文連結。例如：

  `3. 2026/10/09 第 4 場：投票異常標記看不懂（第 3 行「389 7」） https://discord.com/channels/…`

- 日期和場次從標題讀，例如「1009一般場4」是 10/09 第 4 場。標題沒有日期時改用發文日期，並註明「（依發文時間）」；標題最後的數字不像場次（例如接了 6 碼配置）時不寫場次。
- 一次最多列 50 篇，超過的只寫「另有 N 篇沒列出」。
- 最後附上**累計待修正篇數**（不限發文時間），讓大家知道總共積了多少；超過 30 天的不逐篇列出。
- 這週沒有要修的牌譜時，會發一則簡短的「都沒有格式問題」。
- 每週只發一次：頻道最近 100 則訊息裡已經有機器人本週的清單，就不會再發。

## 怎麼修正一篇牌譜

1. 點清單或回覆裡的連結，到那篇貼文。
2. **直接編輯貼文的第一則訊息**（牌譜本文），照回覆裡的提示改好。不用重發，也不用刪掉機器人的回覆。
3. 隔天凌晨的排程會重新讀取；讀得懂就自動收錄，下週的清單就不會再出現這篇。

另外：

- 那局如果已經另外收進「牌譜」分頁，幫貼文加上「已收錄」標籤，就不會再被列出。
- 模擬局請加上「模擬」標籤。

格式重點（照牌譜順序，每行一項）：

- 每次提議一行：隊伍座號連寫（0 = 10 號），可以接投票異常標記，例如 `389 +7`、`469 57-6+`
- 每輪任務結果一行：o 成功、x 失敗，例如 `ooox`
- 湖：持湖者>目標 宣告，例如 `0>8 o`（o = 宣告藍、x = 宣告紅）
- 牌譜之後：`刺客刺殺：座號或 x`；6 碼配置（刺、娜、德、奧、派、梅的座號，例如 `936758`）；玩家名單每人一行 `1.名字` … `9.名字`、`10.名字`
- 貼文標籤三選一：三紅／三藍被刀／三藍躲刺

## 開關

GitHub repo 的 Settings → Secrets and variables → Actions → **Variables**：

| 變數 | 沒設定時 | 作用 |
|---|---|---|
| `DISCORD_IMPORT_WRITE` | 開 | 設成 `false`：每天的排程暫停寫入試算表，這時回覆和清單也只計數、不發。只影響排程；手動執行看 `write` 勾選。 |
| `DISCORD_IMPORT_REPLY` | 開 | 設成 `false`：不在貼文底下回覆。排程和手動執行都不回（就算勾了 `reply`）。 |
| `DISCORD_FIX_LIST` | 開 | 設成 `false`：不發每週清單。排程和手動執行都不發（就算勾了 `fix_list`）。 |
| `DISCORD_FIX_CHANNEL_ID` | 找「牌譜修正」 | 設成頻道 id（只有數字）：清單改發到那個頻道。 |

手動執行（Actions → Import Discord records → Run workflow）：

- `write`（預設不勾）：不勾 = 只算數量，不寫試算表，**也不在 Discord 發任何訊息**。
- `reply`（預設勾）：回覆格式有問題的貼文。
- `fix_list`（預設不勾）：發本週的牌譜修正清單；本週已經發過就略過。想在週一之前先拿到清單，或週一到週三的排程都沒發成功時，手動執行並勾 `write` 和 `fix_list`。

## 機器人需要的 Discord 權限

- **#牌譜紀錄與覆盤**：檢視頻道、讀取訊息歷史、在討論串中傳送訊息；另外要開 Message Content intent。
- **牌譜修正**：檢視頻道、傳送訊息、讀取訊息歷史。頻道名稱要**完全是「牌譜修正」四個字**（不要加表情符號或其他字），不然請設 `DISCORD_FIX_CHANNEL_ID`。

找不到頻道或沒有權限時，GitHub Actions 只會留一則提示（notice），匯入照常進行，不算失敗。

## 公開紀錄

這個 repo 是公開的。GitHub Actions 的 log 和摘要只有數量（例如「30 天內待修正：3 篇」「找到頻道：有」），不含玩家名字、牌譜內容、貼文標題或連結。回覆和清單的內容只出現在 Discord。
