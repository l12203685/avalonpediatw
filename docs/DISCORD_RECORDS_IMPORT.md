# Discord 牌譜自動收錄與格式回覆

每天凌晨 3:17（台灣時間），機器人會讀 Discord 論壇 **#牌譜紀錄與覆盤** 的貼文（一篇貼文 = 一局），把讀得懂的牌譜收進戰績試算表的「Discord匯入」分頁。3:47 戰績分析快取更新時，「牌譜」和「Discord匯入」會一起算進去。

不會重複收錄：已經在「牌譜」分頁的局、標了「已收錄」的貼文都會跳過；標「模擬」的貼文不收錄。

已經收進「Discord匯入」的貼文，事後改了（例如把打錯的玩家名字改對），發文 90 天內的每天也會重新讀，改寫「Discord匯入」裡那一列（見〈貼文改過之後〉）。

程式：`packages/server/discord_records_import.py`；排程：`.github/workflows/import-discord-records.yml`。

## 機器人在貼文底下回覆什麼

牌譜格式有問題、沒辦法自動收錄時，機器人會在那篇貼文的討論串回一則 **「🤖 牌譜格式檢查」**，內容包括：

- 第幾行有問題、那一行寫了什麼、原因
- 格式提示
- 「修好後不用做別的，下次排程會自動重新讀取」

規則：

- 只回最近 14 天發的貼文，**每篇只回一次**（回覆被刪掉也不會再回）。
- 每次最多回 20 篇，其餘的下一次再回。
- 不會 @ 任何人；引用的那一行裡如果有連結或 @，只會顯示成文字。
- 以下貼文不回：標「已收錄」或「模擬」、第一則訊息被刪掉或是空白、純討論的貼文（沒有牌譜、沒有結果標籤、也沒有 6 碼配置）。

## 「待修正」標籤

需要修正的牌譜貼文，機器人會加上論壇標籤 **「待修正」**；修好之後自動拿掉。負責修正的人在論壇上方的標籤篩選選「待修正」，就能看到所有還沒修好的貼文。

哪些貼文會加上：

- 跟上面格式回覆同一批規則：因為格式問題無法自動收錄的牌譜。標「已收錄」或「模擬」、第一則訊息被刪掉或是空白、純討論的貼文（沒有牌譜、沒有結果標籤、也沒有 6 碼配置）都不加。
- 只加在**最近 90 天**發的貼文上（格式回覆只回 14 天內的；標籤看得比較久）。

什麼時候拿掉：

- 牌譜修好、機器人讀得懂之後（不管貼文是多久以前發的），下一次排程就拿掉。讀得懂但跟「牌譜」分頁或另一篇重複的，也算不用修。
- 貼文加上「已收錄」或「模擬」標籤時。
- 第一則訊息被刪掉、變成空白、或改成不像牌譜的貼文：機器人無法判斷，標籤留著，請人工處理。

其他規則：

- 機器人**只動「待修正」這一個標籤**，貼文的其他標籤一個都不會改。
- 每次最多改 30 篇（先拿掉修好的，再加新的，新貼文優先），其餘的下一次再改。標籤已滿或鎖定而略過的貼文不佔名額。
- 貼文已經有 5 個標籤（Discord 的上限）時不加。鎖定的貼文不加；但鎖定的貼文修好了、或標了「已收錄」／「模擬」，標籤一樣會拿掉，免得一直留在「待修正」篩選裡。
- 已封存（一段時間沒人留言）的貼文，Discord 規定要先重新開啟才能改標籤；機器人改完會馬上把它封存回去，不會一直留在進行中的貼文裡。（有收到格式回覆的貼文，回覆本身就會讓它重新開啟，這種貼文改完標籤不會再封存。）
- 這個標籤由機器人管理：讀得懂的貼文上的「待修正」會被拿掉；沒修好的貼文被手動拿掉標籤，隔天會再加回去。請不要拿它標記其他問題。
- 論壇沒有「待修正」標籤時，機器人會自己建立（需要「管理頻道」權限）。沒有權限時 GitHub Actions 會留一則提示，請在論壇的「編輯頻道 → 標籤」新增一個名稱**完全是「待修正」三個字**的標籤，下一次排程就會開始用。論壇最多 20 個標籤，滿了要先刪一個。可以把它設成只有管理者能加的標籤，機器人一樣能加。
- 開關跟著格式回覆：`DISCORD_IMPORT_REPLY` 設成 `false` 或手動執行沒勾 `reply` 時，標籤也不動；沒勾 `write` 時只計數、不改。（命令列另有 `--no-tag` 可以只關標籤。）

## 怎麼找出所有要修的牌譜（用 Discord 搜尋，備用）

最簡單是在論壇上方的標籤篩選選「待修正」（見上一節）。以下的搜尋是備用方法，也找得到 14 天內機器人回過的每一篇。

Edward 2026-10-13：「應該不用牌譜修正了」——每週清單已經停掉（排程不再發）。用搜尋找的方法：
機器人回過「🤖 牌譜格式檢查」的貼文，就是格式有問題、還沒收進戰績的那幾篇。

1. 在 Discord 伺服器右上角的搜尋框輸入：

   `from:機器人名稱 in:#牌譜紀錄與覆盤`

   （打 `from:` 之後選單會列出成員，選阿瓦隆機器人；打 `in:` 之後選 #牌譜紀錄與覆盤。）
   機器人在這個論壇裡只會發「🤖 牌譜格式檢查」這一種訊息，所以這樣搜就是它的**每一則**回覆，不用靠中文關鍵字。
   想在整個伺服器找，也可以搜 `from:機器人名稱 牌譜格式檢查`。
2. 搜尋結果依時間排列；點一則就會跳到那篇貼文。
3. 修好的貼文不會從搜尋結果消失（回覆還在），但隔天凌晨就會被收錄；要確認有沒有收進去，看網站戰績或試算表的「Discord匯入」分頁。

補充：

- 論壇上方的「篩選」是依**標籤**篩（三紅／三藍被刀／三藍躲刺、線瓦／面瓦、已收錄、模擬、待修正）；要找需要修正的貼文，選「待修正」最直接。
- 機器人只回**最近 14 天**發的貼文；更早的格式問題不會有回覆，也就搜不到（大多已經標「已收錄」或另外收在「牌譜」分頁）。
- 機器人每次回覆也會記在戰績試算表的「Discord回覆」分頁（貼文 id、回覆時間、原因）；貼文連結是
  `https://discord.com/channels/1132682489840812113/貼文id`。
- 真的需要一份清單時，管理者可以手動執行 Actions → Import Discord records，勾 `write` 和 `fix_list`，清單會發到「牌譜修正」頻道（見下方「開關」）。

## 怎麼修正一篇牌譜

1. 在論壇用標籤篩選「待修正」找到那篇貼文（或用上面的搜尋、或點機器人回覆所在的討論串）。
2. **直接編輯貼文的第一則訊息**（牌譜本文），照回覆裡的提示改好。不用重發，也不用刪掉機器人的回覆。
3. 隔天凌晨的排程會重新讀取；讀得懂就自動收錄。修好後「待修正」標籤也會在下一次排程自動拿掉。

另外：

- 已經收錄過的貼文發現打錯（例如玩家名字）：一樣直接編輯第一則訊息，發文 90 天內的隔天會更新（見〈貼文改過之後〉）。
- 那局如果已經另外收進「牌譜」分頁，幫貼文加上「已收錄」標籤，機器人就不會再理它。
- 模擬局請加上「模擬」標籤。

格式重點（照牌譜順序，每行一項）：

- 每次提議一行：隊伍座號連寫（0 = 10 號），可以接投票異常標記，例如 `389 +7`、`469 57-6+`
- 每輪任務結果一行：o 成功、x 失敗，例如 `ooox`
- 湖：持湖者>目標 宣告，例如 `0>8 o`（o = 宣告藍、x = 宣告紅）
- 牌譜之後：`刺客刺殺：座號或 x`；6 碼配置（刺、娜、德、奧、派、梅的座號，例如 `936758`）；玩家名單每人一行 `1.名字` … `9.名字`、`10.名字`
- 貼文標籤三選一：三紅／三藍被刀／三藍躲刺

## 貼文改過之後

2026-10-13 起，每天的排程除了收新貼文，也會重新讀**已經收進「Discord匯入」、發文 90 天內**的貼文：

- 貼文的第一則訊息、標題、結果標籤（三紅／三藍被刀／三藍躲刺）或分類標籤（線瓦／面瓦）改過，就重新解析，把「Discord匯入」裡那篇的那一列改成新的內容。只寫內容有變的格子：「匯入時間」保留第一次收錄的時間，「更新時間」寫這次改寫的時間；有人在那一列手動加的其他欄位（包括公式）不會被碰到。寫入前會再確認那一列還是同一篇貼文；讀取到寫入之間有人排序或刪列，這次就不寫、隔天再改。
- 只改了評論、牌譜內容沒變：戰績不動，只把那一列的 `discord_hash` 更新成新版本（之後不會每天重複判斷成「有修改」）。
- 改完之後讀不懂：保留修改前收錄的那一列（戰績先沿用舊版本），貼文會加上「待修正」標籤（14 天內的貼文另有一則格式回覆），照提示改好，隔天就會更新。
- 起始訊息被刪掉或清空：保留原本那一列，不會自動刪除。
- 後來加上「模擬」標籤：保留原本那一列，請管理者到「Discord匯入」分頁手動刪掉（刪了之後，戰績分析更新要手動執行一次並勾 `allow_shrink`，因為總局數會變少）。
- 標了「已收錄」的貼文、或那局已經抄進「牌譜」分頁：**不會動**。「牌譜」分頁是人工維護的，那裡的錯誤請直接在「牌譜」分頁改。
- 只改「Discord匯入」分頁，從不寫「牌譜」或其他分頁。
- 每次最多重讀 200 篇：最新的 100 篇每天都讀（修正通常發生在發文後不久），其餘的每天輪流讀 100 篇，幾天內每篇都會讀到；只有真的改過的列才會寫回試算表（一次寫完）。重讀途中 Discord 出錯：這次重讀到此為止、隔天再讀，新貼文照常收錄。
- 3:47 的戰績分析更新本來會擋下「既有玩家局數變少」（防止誤刪資料）；「Discord匯入」因貼文修改而改寫的列（看「更新時間」）可以解釋的減少會放行，例如打錯的名字少了那一局。Actions 紀錄只寫數量、不寫玩家名字。
- 判斷「改過沒有」：每列記一個 `discord_hash`（標題、相關標籤、起始訊息算出來的雜湊）；這個欄位出現前收錄的列，改看 Discord 記錄的「編輯時間」是否晚於「匯入時間」／「更新時間」，以及標題、標籤是否和那列記的一樣。舊的「Discord匯入」分頁第一次寫入時，會在最後面自動加上 `discord_hash`、`更新時間` 兩欄。
- 超過 90 天的貼文不再自動重讀。需要時請在本機執行 `python packages/server/discord_records_import.py --recheck-days 365`，或直接改「Discord匯入」那一列；手動改玩家名字時請同時把那一列的「更新時間」填成當下時間（`YYYY-MM-DD HH:MM:SS`），否則隔天的戰績分析更新會因為舊名字局數變少而停下來。

## 常見問題

**問：已經自動收錄的牌譜，一兩個月後發現玩家 id 打錯、去改了貼文，每天的匯入會跟著更新嗎？**

答：會（2026-10-13 起）。發文 90 天內的貼文，改好之後隔天凌晨 3:17 的排程會重新讀到，改寫「Discord匯入」裡那一列；3:47 戰績分析更新時就會用改過的名字（打錯的那個名字少掉那一局，守門會放行）。這是 2026-10-13 才加上的：在那之前，已收錄的貼文改了不會更新；現在連之前就收錄的貼文，只要發文在 90 天內也會重新讀。
例外：標了「已收錄」、或那局已經抄進「牌譜」分頁的，機器人不動，由管理者在「牌譜」分頁手動改（改了名字之後，戰績分析更新要由管理者手動執行一次並勾 `allow_shrink`）；發文超過 90 天的，請找管理者改「Discord匯入」那一列（見上面）。

**問：名字的大小寫要和以前一模一樣嗎？**

答：不用（2026-10-13 起）。只差英文大小寫、全形半形或前後空白的名字（例如 `Nova`、`NOVA`、`ｎｏｖａ`）算同一位玩家，戰績會合併，網站和機器人查詢也不分大小寫；顯示用最常出現的寫法。名字其他地方打錯（多一個字、換了別的字）還是會被當成另一個人，請照上面的方式修正。

## 開關

GitHub repo 的 Settings → Secrets and variables → Actions → **Variables**：

| 變數 | 沒設定時 | 作用 |
|---|---|---|
| `DISCORD_IMPORT_WRITE` | 開 | 設成 `false`：每天的排程暫停寫入試算表，這時回覆也只計數、不發。只影響排程；手動執行看 `write` 勾選。 |
| `DISCORD_IMPORT_REPLY` | 開 | 設成 `false`：不在貼文底下回覆。排程和手動執行都不回（就算勾了 `reply`）。 |
| `DISCORD_FIX_LIST` | 開 | 設成 `false`：手動勾了 `fix_list` 也不發清單。（排程本來就不發。） |
| `DISCORD_FIX_CHANNEL_ID` | 找「牌譜修正」 | 設成頻道 id（只有數字）：手動清單改發到那個頻道。 |

貼文改過之後的重新讀取沒有開關變數，跟著寫入走：寫入時改寫，dry run 只計數。命令列 `--recheck-days N`（預設 90）、`--recheck-limit N`（預設 200），設 0 就關閉。

手動執行（Actions → Import Discord records → Run workflow）：

- `write`（預設不勾）：不勾 = 只算數量，不寫試算表，**也不在 Discord 發任何訊息**。
- `reply`（預設勾）：回覆格式有問題的貼文。
- `fix_list`（預設不勾）：在「牌譜修正」頻道發一份最近 30 天的待修正清單（每週最多一次）。2026-10-13 起只有手動才會發。

## 機器人需要的 Discord 權限

- **#牌譜紀錄與覆盤**：檢視頻道、讀取訊息歷史、在討論串中傳送訊息、**管理討論串**（加上和拿掉「待修正」標籤，以及改完後把已封存的貼文封存回去）；另外要開 Message Content intent。第一次建立「待修正」標籤需要**管理頻道**；也可以由管理者手動新增這個標籤，就不需要給管理頻道。

  改標籤時被拒絕（403，沒有「管理討論串」）：GitHub Actions 會留一則提示（notice），那一次就不再改標籤，匯入和回覆照常進行，不算失敗。只是某一篇貼文讀不到（讀取時 403）不算缺這個權限：那篇記一筆錯誤，其他貼文照改。
  - 2026-10-13 手動執行的結果：14 天內需要回覆的貼文 1 篇、已回覆 1 篇、沒有權限（403）0 篇，所以「在討論串中傳送訊息」目前是夠的；「管理討論串」是否已給，要看第一次加標籤的 Actions 摘要。
- **牌譜修正**（只有手動清單用得到）：檢視頻道、傳送訊息、讀取訊息歷史。頻道名稱要**完全是「牌譜修正」四個字**（不要加表情符號或其他字），不然請設 `DISCORD_FIX_CHANNEL_ID`。

找不到頻道或沒有權限時，GitHub Actions 只會留一則提示（notice），匯入照常進行，不算失敗。

## 公開紀錄

這個 repo 是公開的。GitHub Actions 的 log 和摘要只有數量（例如「本次已回覆：1；沒有發言權限（403）：0」），不含玩家名字、牌譜內容、貼文標題或連結。回覆和清單的內容只出現在 Discord。

例如「90 天內因格式無法解析且未標「已收錄」的貼文 3 篇（已有標籤 1，待加 2）」「本次已加上：2；已移除：1」「有修改、已更新：1 篇（1 列）」。改標籤遇到 Discord 錯誤時，警告只寫錯誤的種類和次數，例如「PATCH /channels/{thread} HTTP 400 code 50035 ×1」（方法、路徑樣板、HTTP 狀態碼、Discord 錯誤碼），不含貼文編號或內容。
