# Threads 每日一題草稿

用實戰牌譜出 Threads 每日一題，產生每天要貼的草稿。站長 2026-11-17 同意自動發佈：站長把權杖存進 secrets、把 repo 變數 `THREADS_PUBLISH` 設成 `1` 之後，GitHub Actions 每天自動發（見下面〈自動發佈〉）；開關打開之前只試跑。站長也可以照草稿手動發。第一則留言由 ChatGPT 寫（Issue #37）。

## 貼文格式（站長 2026-11-11 定案）

每天發一篇新貼文 A，用「引用」的方式引用昨天的貼文 B。

- B 的內容是問題 1＋解答 0；A 的內容是問題 2＋解答 1。
- A 的第一則留言放跟這題有關的數據冷知識或觀念，加上文章網址。
- 不另外在昨天的貼文底下串答案，不用私訊對答案，也不當天公布。
- 11/17 的題目其實沒有發出去（站長 11/18 確認），程式不再寫死「11/17 已經貼出」。系列起點用正式發的第一天（主控台設定、同步進 `packages/server/threads_live.json` 的 `liveFrom`；repo 變數 `THREADS_LIVE_FROM` 有設就蓋過），都沒設時預設 2026-11-17（`THREADS_START_DATE`；站長 11/17：「我想從11/17開始」）。
- 自動發佈只在**昨天真的有貼文**（`threads-state` 的 `state/<昨天>.json` 有貼文 id，或是站長手動發、補記過的那一天）時，才引用昨天、附昨天的答案，週四／週六才接昨天那一局；昨天沒有貼文（只試跑過、或根本沒發），今天就是獨立的第一篇。

## 怎麼跑

```bash
pnpm --filter @avalon/server threads:draft                        # 今天（台北日期）
pnpm --filter @avalon/server threads:draft -- --date 2026-11-18   # 指定日期
pnpm --filter @avalon/server threads:draft -- --week              # 從 --date（預設今天）起連續 7 天
# 其他選項：--days N、--out <資料夾>、--no-image、--start YYYY-MM-DD（第一篇的日期，預設 2026-11-17）
```

輸出放在 `packages/server/threads_drafts/`，這個資料夾不進 git。每天產生三個檔：

| 檔案 | 內容 |
|---|---|
| `<日期>.md` | 給站長複製貼上：① 新貼文 A（引用昨天的貼文發）、② A 的第一則留言 |
| `<日期>.json` | 同樣的內容，另外記下題目（`pick`）和放進 A 的昨天答案（`answerToYesterday`）。ChatGPT 把第一則留言寫進 `firstComment.text` |
| `<日期>.png` | 輪播第 1 張・題目卡（深色）：左上小圓桌（0 在十二點、順時針 1 2 3 4 沿右邊往下、5 在六點、6 7 8 9 沿左邊往上；你藍色、拇指金圈、看到的紅與隊友紅圈；桌面中間五局任務格）、右上你的視角、下面網站牌譜頁的格子（隊長｜座位 1～0｜結果｜文字紀錄；金盾 = 上隊、白／黑 = 贊成／反對、任務列、湖中列，文字裡值得注意的票綠色）到出題那一刻；「輪到你派 N 人」白字放在右上你的視角下面。一般局 ≤ 1080×1350（Threads 手機 4:5） |

## 新貼文 A 的內容（≤ 500 字）

照站長 11/17 改過的 11/18 草稿：

```
【阿瓦隆每日一題｜週三・1-5 尾派】
你是 5家・忠臣
[第 1 局]
1家 124
2家 260
3家 389
4家 456
輪到你 5家 忠臣 派 3 人，你會派誰？

#阿瓦隆 #梅林 #派西維爾 #亞瑟的忠臣
```

1. 標題（主題）。自動發佈也靠這一行（加上台北日期）在最近的貼文裡認出那一天的那一篇（舊貼文另外認「題號 …」）。
2. 今天的題目：
   - 你的座位和角色。派西附拇指、梅林附看到的紅、刺客附隊友。
   - 到目前的牌譜，每一局開頭一行「[第 N 局]」；縮短時前面幾局寫成「[第 N 局] 任務 …」。
   - 一行「輪到你 <座位>家 <角色> 派 N 人，你會派誰？」（刺殺題「三藍，輪到你 0家 刺客 刺殺，誰是梅林？」）；不寫第幾局第幾次、強制出發。
3. 空一行，「[昨天 <題號> 的答案]」：
   - 真人派了什麼、幾好幾壞、任務結果；
   - 一行純邏輯的理由；
   - 角色代碼和結果；
   - 網站牌譜連結。
4. 空一行，最後一行主題標籤 `#阿瓦隆 #梅林 #派西維爾 #亞瑟的忠臣`。貼文不寫題號（在圖的標題和狀態檔）。

**放不下 500 字時，先縮題目：**
1. 前面幾局只留任務結果和湖。
2. 還是放不下，就只寫「完整局面看圖」。
3. 最後才把答案裡的理由拿掉。

牌譜連結一定留。完整局面都在圖裡。

## 圖（站長 11/17：「圖可以用你提供的格式 不過最好是深色版本 因為質感比較好 也有一致性」）

- **題目圖**：深色卡片。一行標題列（站長 11/17：「title 可以寫 [左上角小 Logo 跟title 字體一樣大] 接 {阿瓦隆百科 ‧ 每日一題: 1-5 第一局尾派 [SV1Q8]} 這樣就好」：左上角小標誌、`阿瓦隆百科 ‧ 每日一題: <決定點＋一句話> [<局號>]`，例如 `1-5 第一局尾派`、`5-1 第五局第一次`、`3-4 派西維爾`、`刺殺`；續圖、答案卡後面加 ` · 牌譜 2/2`、` · 答案`）、你的視角，下面接白字的「輪到你派 N 人」（站長 11/17：「圖裡面不要寫 (第3局第5次，強制出發)」「"輪到你派 4 人"的字 顏色改白色 放到 "你是 5家 忠臣" 旁邊 或 下面」）、座位 1～0、五局的任務格、到目前的牌譜（最後一列只寫「輪到你」）、記號說明。圓桌比之前小約 12%（站長 11/17「圓桌好像可以再小一點點」）。
- **牌譜的寫法**同百科的文字牌譜（隊長＋隊伍 內黑- 外白+，順序同網站）；配色借站長以前 IG「每日一派」：記號 +／- 綠色、任務結果黃色、湖綠色，任務失敗紅、成功綠。
- **只畫到出題那一刻**：之後的派票、任務、湖、角色都不在圖裡（測試直接檢查交給畫圖的資料）。
- **背景**：阿瓦隆百科的標誌（`assets/threads/logo.png`，網站 `logo.png` 的複本）放大當浮水印（不透明度 0.1），標題列左邊放一個小標誌（站長 11/17：「我是希望背景帶有我們的"阿瓦隆百科"logo」）。
- **答案圖**：公布完整答案的日子另附一張（`post.answerImage`），同樣的深色卡片：藍方（派西維爾、梅林）、紅方（刺客、莫甘娜、莫德雷德、奧伯倫），加結果。
- 一張題目圖不拆成多張；牌譜超過 22 行改兩欄。用內附的 Noto Sans TC 以 resvg 轉 PNG，不用瀏覽器，GitHub Actions 上也能跑。

**理由**只用那一家當下看得到的資訊來算：
- 紅方還有幾種可能；
- 真人這隊在幾種裡全好；
- 全好組合最多的隊。

括號裡的百分比是「紅方可能組合中全好的比例」：每一種可能的紅方組合算一樣多，不是校準過的勝率。

**② 第一則留言**由 ChatGPT 填。草稿附上：
- 建議的百科文章，用分享網址 `/w/<id>/`，Threads 會顯示預覽卡片；
- 這一題的關鍵字。

草稿和圖只有座位和牌譜記號，沒有玩家名字。第十個座位寫「0家」。

## 程式與測試

程式在 `packages/server/src/bots/threads/`：
- `plan.ts`：一週的計畫
- `draft.ts`：A 的文字
- `image.ts`：圖
- `generate.ts`：把存檔和題庫接起來；站長選的題（`threads_picks.json`）也在這裡套上
- `publish/daily.ts`：自動發佈的三段（prepare、post、補記手動發的那一天）、內容檢查、狀態檔
- `publish/threadsApi.ts`：Threads API（發文、回覆、查最近的貼文、權杖檢查與續期）
- `publish/instagramApi.ts`：Instagram API（同步發同一篇的圖文、輪播、續期）

指令在 `packages/server/scripts/threadsPublish.ts`，工作流程在 `.github/workflows/threads-publish.yml`。

測試在 `src/__tests__/ThreadsDraft.test.ts`、`src/__tests__/ThreadsPublish.test.ts`（自動發佈用假的 HTTP，不會真的連 Threads）。

## 自動發佈

站長 2026-11-17：「我同意threads 自動發佈」。

### 它做什麼

每天台北時間中午 12 點（repo 變數 `THREADS_POST_HOUR` 可以改）：
1. 產生今天的貼文 A、題目圖、第一則留言，檢查內容：
   - A ≤ 500 字，最後一行剛好一行主題標籤 `#阿瓦隆 #梅林 #派西維爾 #亞瑟的忠臣`；
   - 不寫「10 家／10 號」；
   - 貼文和留言都不含玩家名字。
2. 找昨天那篇的貼文 id（自動發的記在狀態檔；手動發的去自己最近的貼文裡找那一天、標題對得上的那一篇；舊貼文認「題號 昨天的題號」）。
3. 發 A：附圖、引用昨天那篇。第一天或找不到昨天那篇時不引用。
   - 圖照順序：題目卡、牌譜圖、公布完整答案那天的答案卡。兩張以上發成輪播（Threads 的 CAROUSEL：每張先建子項，再建一個帶文字和引用的輪播容器）；只有一張就發單張圖文。
   - 牌譜通常跟題目畫在同一張；太長放不下時才有牌譜續圖，要幾張就幾張（題目卡 → 續圖 2/N … N/N → 答案卡）。答案卡在公布完整答案的那天才有。
   - 續圖一定全部跟著發；畫圖失敗、少了幾張或沒有公開網址時，正式發佈這天不發（那次執行失敗並寫原因）；試跑照常、摘要有警告。
   - Threads 輪播最多 20 張（實際的局用不到）；IG 輪播最多 10 張，超過時 IG 這天不同步、Threads 照發。
   - 貼文的牌譜縮成「完整局面看圖」、圖卻沒有產生或沒有公開網址時，也一樣不發（只發文字會是不完整的題目）。
4. 先把 A 的 id 記下來，再把第一則留言回在 A 底下。
5. 把貼文網址記進 `threads-state` 分支的 `state/<日期>.json`。

不會重複發：狀態檔有這一天的貼文 id 就跳過；沒有的話先看自己最近的貼文裡有沒有今天發的、標題一樣的那一篇（舊貼文認「題號 今天的題號」），有就補記、不再發。
只認當天（台北日期）發的那篇：站長選了之前某天發過的同一題時，舊的那篇不會被當成今天的（找昨天那篇引用時也只認昨天發的）。
A 發了、第一則留言沒成功時（狀態檔 `commentId` 是 `null`），之後每小時的執行不再發 A，只補發留言。
發佈的回應不明（網路斷線、429、5xx）時不盲目重發：先看自己最近的貼文（或自己的回覆）和容器狀態，已經發出去就沿用那一篇。
每次真的發出東西（A、留言）就馬上把狀態檔推上 `threads-state`；發留言前也先查這一篇底下有沒有自己帳號的回覆（照分頁翻，最多 20 頁；翻不完就先不發），有就沿用。
正式發佈前查不到權杖的權限（`debug_token` 沒回應或沒列權限）就不發，直接讓那次執行失敗；試跑不受影響。

內容檢查沒過（例如疑似玩家名字）時，執行紀錄、摘要和試跑附件都不放貼文和留言的內容，只放檢查訊息（這個 repo 的 Actions 紀錄是公開的）。

### 誰來觸發（伺服器每天觸發，GitHub 排程當備援）

GitHub 自己的排程對這個 repo 很不準：每日排程常晚 7–8 小時才跑，這個工作流程每小時的排程（`'7 * * * *'`）從生效到 11/17 一次都沒跑過。所以改成跟每晚記錄員一樣，由 Render 上一直開著的伺服器自己觸發：

- 台北時間每天 **12:07**（`THREADS_POST_HOUR` 點 07 分）到 23:00 之間，伺服器用 GitHub 的 workflow_dispatch 觸發一次 `threads-publish.yml`（ref `main`，`mode=auto`、`date` 空白＝今天）。觸發失敗下一分鐘再試；成功後當天不再觸發。程式在 `packages/server/src/services/threadsDispatch.ts`。
- 伺服器重啟後同一天可能再觸發一次，沒關係：工作流程有 concurrency（同一組排隊、不取消進行中的），而且 `threads-state` 有這一天的貼文 id 就跳過，不會重複發。
- GitHub 的排程留著當備援；伺服器那次已經發了，排程跑到時一樣跳過。
- 伺服器的環境變數（Render → Environment）：
  - `GITHUB_DISPATCH_TOKEN`：跟補位機器人、每晚記錄員共用同一把（只給這個 repo、Actions: Read and write，就能觸發這個 repo 的任何 workflow），不用另外建。沒設就不觸發。
  - `THREADS_POST_HOUR`（選填，0–22，預設 `12`）：幾點觸發。跟 repo 變數 `THREADS_POST_HOUR` 是兩個地方，要改時兩邊一起改（手動觸發不看 repo 變數的時間，伺服器幾點觸發就幾點發）。
  - `THREADS_DISPATCH=off`（選填）：停掉伺服器觸發（只剩 GitHub 排程）。

### 正式發的開關（站長在主控台設，不用動 GitHub 變數）

正式發的起始日與暫停由站長在**主控台**的「Threads／IG 上線」設定。主控台 GitHub 讀不到，所以 Claude 每天台北 08:00 的同步把主控台的值寫進 `packages/server/threads_live.json`（commit 到 main）：

```json
{ "liveFrom": "2026-11-20", "paused": false, "note": "…" }
```

- `liveFrom`：正式發的第一天（YYYY-MM-DD，台北）；`null`＝只試跑不發。
- `paused`：`true` 時自動的執行一律只試跑（不管起始日）。
- 改了主控台要等下一次台北 08:00 的同步寫進檔案才生效；發文在 12:07，所以 08:00 前改的當天就算數，08:00 後改的從隔天算。主控台會顯示「Claude 上次同步進 repo」的值；同步沒跑成功時檔案還是舊的，暫停不會生效，要當天馬上停請照下面「馬上停」把兩個發文變數關掉。
- repo 變數 `THREADS_LIVE_FROM`（選用，相容舊設定）：有設就蓋過檔案的 `liveFrom`，只管起始日；`paused` 照樣有效。
- 工作流程第一步在執行當下用 API 讀 **main 上最新的**檔（排隊或重跑的執行也讀得到後來同步的暫停；發文的程式照舊用這次執行的 commit）。**例外**：GitHub 的「重跑」用的是原本那次的工作流程版本，這個閘門合併之前建立的執行重跑時不會讀這個檔、也不管暫停；要重發請開新的一次執行，不要重跑舊的。自動的執行只有在檔案讀得到、是合法的 JSON、`paused` 是布林值 `false` 時才可能正式發；讀不到、壞掉、`paused` 沒有或不是 true/false 一律只試跑，**有設 repo 變數也一樣**。
- 起始日（檔案或變數）要是真的日期：`2026-02-30` 這種不存在的日期當作沒設＝只試跑。閘門算出來的起始日也傳給產生貼文、補記手動發的那兩步當系列起點。

**起始日的閘門一樣管伺服器觸發**：沒有起始日（檔案 `liveFrom` 是 `null`、也沒設 repo 變數）、今天（或要發的日期）早於那一天，或 `paused` 是 `true` 時，「自動」的執行一律只試跑，Threads 和 IG 都是。自動＝排程，或手動觸發選 `mode=auto`（伺服器觸發用的就是這個）。

| 觸發方式 | 起始日之前（或沒有起始日、暫停中） | 起始日當天起 |
|---|---|---|
| GitHub 排程 | 只試跑 | 照 `THREADS_PUBLISH`／`INSTAGRAM_PUBLISH` |
| 伺服器觸發、手動選 `auto` | 只試跑 | 照 `THREADS_PUBLISH`／`INSTAGRAM_PUBLISH` |
| 手動選 `dry-run` | 只試跑 | 只試跑 |
| 手動選 `record-manual` | 只補記，不發文、不碰 IG | 同左 |

### 一開始只試跑

repo 變數 `THREADS_PUBLISH` 不是 `1` 時只試跑：照常產生、檢查，把要發的貼文、留言和圖放在那次執行的摘要和附件（Actions → Threads 每日發文 → 那一次 → Artifacts），不會碰 Threads。

## Instagram 同步

站長 2026-11-17：「我想順便一齊開通IG 的權限 同步發文」。

Threads App 裡「同時分享到 IG」的按鈕沒有 API 可以用，所以另外用 Instagram API 發同一篇。

### 它做什麼

每天 Threads 那篇發完後（或同一次執行裡），把同一篇發到 IG：
- **圖**：跟 Threads 同一組、同樣順序（題目卡、牌譜圖、答案卡），每張轉成 1080×1350 的 JPEG（IG 只收 JPEG，長寬比要在 4:5 到 1.91:1 之間），放在 `threads-state` 分支的 `images/<日期>*.jpg`。兩張以上發成輪播。
- **說明**：Threads 那篇的文字，後面接第一則留言（觀念加文章網址），最後一行主題標籤。
  - IG 沒有「引用貼文」，昨天的答案照樣寫在說明裡。
  - IG 說明裡的網址不能點，牌譜和文章網址照純文字放。
- **不重複發**：狀態檔記了這一天的 IG 貼文 id 就跳過；IG 最近的貼文裡已經有今天發的、標題一樣的那一篇就補記、不再發。
  發佈的回應不明時不盲目重發，先看 IG 最近的貼文和容器狀態；發出去後馬上把狀態檔推上 `threads-state`。
- **先確認權杖**：正式同步前先查 IG 帳號和發文額度（要 `instagram_business_content_publish`）；確認不了就跳過 IG、摘要出警告，不影響 Threads。
- **跟 Threads 分開**：IG 失敗不影響 Threads，反過來也一樣。JPEG 轉檔失敗時當天不同步 IG（摘要有警告），Threads 照常上傳、發文。
  題目不完整的日子（跟 Threads 同一套檢查：少了續圖或續圖的網址、要看圖卻沒有圖）IG 也不同步。

### 開關

- 沒有 secret `INSTAGRAM_ACCESS_TOKEN`：完全不碰 IG。
- 有權杖、但 repo 變數 `INSTAGRAM_PUBLISH` 不是 `1`：只試跑，IG 說明和 JPEG 放在那次執行的摘要和附件。
- `INSTAGRAM_PUBLISH`＝`1`：正式同步。
- 手動執行選 `dry-run` 時一律只試跑。

### 站長要做的（一次）

1. **IG 改成專業帳號**：IG App → 設定 → 帳號類型和工具 → 切換為專業帳號（創作者或商家都可以）。
2. **在同一個 Meta 應用程式加上 Instagram**：developers.facebook.com → 你的應用程式 → 新增使用案例「Instagram API（用 Instagram 登入）」。
3. **權限**：加上 `instagram_business_basic`、`instagram_business_content_publish`。
4. **把自己加成 Instagram 測試人員**：應用程式角色 → 新增 Instagram 測試人員（填 IG 帳號），再到 IG 網頁版「設定 → 應用程式和網站 → 測試人員邀請」接受。
5. **產生權杖**：在 Instagram 使用案例的「API 設定」裡，對自己的 IG 帳號按「產生權杖」，得到長效權杖（60 天）。
6. **放進 GitHub**（Settings → Secrets and variables → Actions）：
   - Secret `INSTAGRAM_ACCESS_TOKEN`＝IG 權杖。
   - Secret `INSTAGRAM_USER_ID`＝IG 帳號 id（可以不填，會用權杖查）。
   - 權杖不要貼在對話、Issue 或程式裡。
7. **先試跑**：Actions → Threads 每日發文 → Run workflow，mode 選 `dry-run`，看摘要裡的「Instagram 說明」和附件裡的 JPEG。
8. **打開**：Variables 新增 `INSTAGRAM_PUBLISH`＝`1`。
9. **要停**：把 `INSTAGRAM_PUBLISH` 改成 `0` 或刪掉，IG 馬上回到只試跑；刪掉 `INSTAGRAM_ACCESS_TOKEN` 就完全不碰 IG。

- IG 每 24 小時最多用 API 發 50 篇，每天一篇不會碰到。

    每欄都能篩（任務、角色、座位、題型多選；題號、拇指、湖文字含；S 最低值），每一局「選給…」只列主題對得上、還沒鎖住的日子。
  - 頁面附帶 `candidates.json`、`games.json`（`threads:candidates` 產生）；站長選的寫進頁面資料庫的 `picks/<日期>`（`{ date, exerciseId, nextExerciseId, chosenAt, … }`），只有擁有者能寫。
  - 週三、週五選了能連著打的局，隔天自動接同一局；週四、週六另選就改出獨立的題目。今天和以前的日子鎖住（已經發出去的題目由存下來的草稿保護）。
- **選擇的正本：** commit 進 repo 的 `packages/server/threads_picks.json`（自動發佈 #48 的格式）：`{ "version": 1, "picks": { "YYYY-MM-DD": "<題號>" } }`。
  產生器只有一條選題的路：`pickOverride`（存下來＝已經發出去的那一天優先；選的題不是那天主題能出的就照計畫，原因寫進 `warnings`）。
  選局頁列出來的題號（`optionsFor`）跟 `pickOverride` 用同一套池子，一定接受。
- **腳本：** `threads:candidates`（`--picks` 預設 `threads_picks.json`；輸出 `candidates.json`、`games.json`，不進 git）、`threads:draft -- --picks <檔>`。
  兩個腳本讀同一份輸入（`src/bots/threads/inputs.ts`）：選的每一天都用（含今天和過去的日子：前一天選的今天的題目、昨天的答案都要對上），
  已經發出去的以存下來的草稿（`threads_drafts/<日期>.json`；`threads:candidates` 用 `--drafts` 指定）為準。
  `--picks` 也接受選局頁資料庫匯出的 `[{ "date": …, "exerciseId": … }]`。

### 每天早上 8 點（台北）的工作

1. 讀選局頁資料庫的 `picks` 集合（ArtifactData `list`，collection `picks`），今天之後的日子
   同步進 `packages/server/threads_picks.json`（`picksFileBody`，日期排好；今天和過去的日子保留檔案裡原本的，不刪）；有變動就 commit（選擇的正本在 repo）。
2. 產生今天的草稿（或由自動發佈 #48 讀 `threads_picks.json` 發文）。
3. 重跑 `threads:candidates -- --today <今天>`，把新的 `candidates.json`、`games.json` 更新到選局頁（今天鎖住、後面的日子照選擇重排）。
