# Threads 每日一題草稿

用實戰牌譜出 Threads 每日一題，產生每天要貼的草稿。站長 2026-11-17 同意自動發佈：站長把權杖存進 secrets、把 repo 變數 `THREADS_PUBLISH` 設成 `1` 之後，GitHub Actions 每天自動發（見下面〈自動發佈〉）；開關打開之前只試跑。站長也可以照草稿手動發。第一則留言由 ChatGPT 寫（Issue #37）。

## 貼文格式（站長 2026-11-11 定案）

每天發一篇新貼文 A，用「引用」的方式引用昨天的貼文 B。

- B 的內容是問題 1＋解答 0；A 的內容是問題 2＋解答 1。
- A 的第一則留言放跟這題有關的數據冷知識或觀念，加上文章網址。
- 不另外在昨天的貼文底下串答案，不用私訊對答案，也不當天公布。
- 第一篇是 **2026-11-17**（`THREADS_START_DATE`），題目是 36AKW-2-5。那一天的 A 只有題目，沒有昨天的答案。

## 怎麼跑

```bash
pnpm --filter @avalon/server threads:draft                        # 今天（台北日期）
pnpm --filter @avalon/server threads:draft -- --date 2026-11-18   # 指定日期
pnpm --filter @avalon/server threads:draft -- --week              # 從 --date（預設今天）起連續 7 天
# 其他選項：--days N、--out <資料夾>、--no-image、--start YYYY-MM-DD（第一篇的日期，預設 2026-11-17）
```

輸出放在 `packages/server/threads_drafts/`，這個資料夾不進 git。每天產生三個檔：

| 檔案 | 內容 |
|---|---|
| `<日期>.md` | 給站長複製貼上：① 新貼文 A（引用昨天的貼文發）、② A 的第一則留言 |
| `<日期>.json` | 同樣的內容，另外記下題目（`pick`）和放進 A 的昨天答案（`answerToYesterday`）。ChatGPT 把第一則留言寫進 `firstComment.text` |
| `<日期>.png` | 輪播第 1 張・題目卡（深色）：左上小圓桌（0 在十二點、順時針 1 2 3 4 沿右邊往下、5 在六點、6 7 8 9 沿左邊往上；你藍色、拇指金圈、看到的紅與隊友紅圈；桌面中間五局任務格）、右上你的視角、下面網站牌譜頁的格子（隊長｜座位 1～0｜結果｜文字紀錄；金盾 = 上隊、白／黑 = 贊成／反對、任務列、湖中列，文字裡值得注意的票綠色）到出題那一刻、最後是「輪到你派 N 人」。一般局 ≤ 1080×1350（Threads 手機 4:5） |
| `<日期>-grid.png` | 只有牌譜太長時才有・牌譜（續）：題目卡先把列高縮到最小 30，還放不下才把後面的列畫在這張（`post.gridImage`）。下週的樣本裡第 4 局、第 5 局與刺殺題會用到 |
| `<日期>-answer.png` | 答案卡（只有公布完整答案的日子）：昨天那一局的角色，紅方一格在上（刺娜德奧）、藍方一格在下（派梅），加結果。週四、週六接著打同一局，不附 |

站長 11/17：「我希望順便呈現牌譜的視覺化版本」「腳色順序應該是 刺娜德奧派梅」「希望能夠像圍著圈圈 (圓桌武士) 的方式呈現 座位」，看過樣張後「我希望 5/0 在六點鐘跟十二點鐘方向 然後縮小一點 跟題目在同一張圖一起出現」。草稿的 `post.image`／`post.gridImage`（只有牌譜太長時）／`post.answerImage` 依序發成同一篇的輪播；只能發一張圖時發 `image`。

已經有 `<日期>.json` 的日子，會沿用檔案裡的題目和第一則留言，重跑不會換題。所以就算題庫或牌譜連結之後更新了，昨天貼出去的題目和今天 A 裡的答案還是對得上。

## 新貼文 A 的內容（≤ 500 字）

1. 標題（主題）。
2. 今天的題目：
   - 你的座位和角色。派西附拇指、梅林附看到的紅、刺客附隊友。
   - 到目前的牌譜。
   - 輪到你做什麼（站長 11/17：「文字部分則是主題 & 牌譜」，作答方式不另寫一行）。
3. 「── 昨天 題號 的答案 ──」：
   - 真人派了什麼、幾好幾壞、任務結果；
   - 一行純邏輯的理由；
   - 角色代碼和結果；
   - 網站牌譜連結。
4. 題號（只寫「題號 XXXXX-1-5」），以及最後一行的主題標籤 `#阿瓦隆`（站長 2026-11-17）。

**放不下 500 字時，先縮題目：**
1. 前面幾局只留任務結果和湖。
2. 還是放不下，就只寫「完整局面看圖」。
3. 最後才把答案裡的理由拿掉。

牌譜連結一定留。完整局面都在圖裡。

## 圖（站長 11/17：「圖可以用你提供的格式 不過最好是深色版本 因為質感比較好 也有一致性」）

- **題目圖**：深色卡片。標題列（阿瓦隆每日一題、主題、題號）、你的視角、座位 1～0（你藍、拇指金、看到的紅／隊友紅、自己湖到的）、五局的任務格、到目前的牌譜、藍色的「輪到你…」、記號說明。
- **牌譜的寫法**同百科的文字牌譜（隊長＋隊伍 內黑- 外白+，順序同網站）；配色借站長以前 IG「每日一派」：記號 +／- 綠色、任務結果黃色、湖綠色，任務失敗紅、成功綠。
- **只畫到出題那一刻**：之後的派票、任務、湖、角色都不在圖裡（測試直接檢查交給畫圖的資料）。
- **背景**：阿瓦隆百科的標誌（`assets/threads/logo.png`，網站 `logo.png` 的複本）放大當浮水印（不透明度 0.1），標題列右邊放一個小標誌（站長 11/17：「我是希望背景帶有我們的"阿瓦隆百科"logo」）。
- **答案圖**：公布完整答案的日子另附一張（`post.answerImage`），同樣的深色卡片：藍方（派西維爾、梅林）、紅方（刺客、莫甘娜、莫德雷德、奧伯倫），加結果。
- 一張題目圖不拆成多張；牌譜超過 22 行改兩欄。用內附的 Noto Sans TC 以 resvg 轉 PNG，不用瀏覽器，GitHub Actions 上也能跑。

**理由**只用那一家當下看得到的資訊來算：
- 紅方還有幾種可能；
- 真人這隊在幾種裡全好；
- 全好組合最多的隊。

括號裡的百分比是「紅方可能組合中全好的比例」：每一種可能的紅方組合算一樣多，不是校準過的勝率。

**② 第一則留言**由 ChatGPT 填。草稿附上：
- 建議的百科文章，用分享網址 `/w/<id>/`，Threads 會顯示預覽卡片；
- 這一題的關鍵字。

草稿和圖只有座位和牌譜記號，沒有玩家名字。第十個座位寫「0家」。

## 自動發佈

站長 2026-11-17：「我同意threads 自動發佈」。

### 它做什麼

每天台北時間中午 12 點（repo 變數 `THREADS_POST_HOUR` 可以改）：
1. 產生今天的貼文 A、題目圖、第一則留言，檢查內容：
   - A ≤ 500 字，最後一行剛好一個 `#阿瓦隆`；
   - 不寫「10 家／10 號」；
   - 貼文和留言都不含玩家名字。
2. 找昨天那篇的貼文 id（自動發的記在狀態檔；手動發的去自己最近的貼文裡找「題號 昨天的題號」）。
3. 發 A：附圖、引用昨天那篇。第一天或找不到昨天那篇時不引用。
   - 牌譜太長、題目卡要第二張續圖的那天：這條管線只發一張圖，正式發佈這天不發（那次執行失敗並寫原因）；試跑照常、摘要有警告。
   - 貼文的牌譜縮成「完整局面看圖」、圖卻沒有產生或沒有公開網址時，也一樣不發（只發文字會是不完整的題目）。
4. 先把 A 的 id 記下來，再把第一則留言回在 A 底下。
5. 把貼文網址記進 `threads-state` 分支的 `state/<日期>.json`。

不會重複發：狀態檔有這一天的貼文 id 就跳過；沒有的話先看自己最近的貼文裡有沒有「題號 今天的題號」，有就補記、不再發。
只認當天（台北日期）發的那篇：站長選了之前某天發過的同一題時，舊的那篇不會被當成今天的（找昨天那篇引用時也只認昨天發的）。
A 發了、第一則留言沒成功時（狀態檔 `commentId` 是 `null`），之後每小時的執行不再發 A，只補發留言。
發佈的回應不明（網路斷線、429、5xx）時不盲目重發：先看自己最近的貼文（或自己的回覆）和容器狀態，已經發出去就沿用那一篇。
每次真的發出東西（A、留言）就馬上把狀態檔推上 `threads-state`；發留言前也先查這一篇底下有沒有自己帳號的回覆（照分頁翻，最多 20 頁；翻不完就先不發），有就沿用。
正式發佈前查不到權杖的權限（`debug_token` 沒回應或沒列權限）就不發，直接讓那次執行失敗；試跑不受影響。

內容檢查沒過（例如疑似玩家名字）時，執行紀錄、摘要和試跑附件都不放貼文和留言的內容，只放檢查訊息（這個 repo 的 Actions 紀錄是公開的）。

### 一開始只試跑

repo 變數 `THREADS_PUBLISH` 不是 `1` 時只試跑：照常產生、檢查，把要發的貼文、留言和圖放在那次執行的摘要和附件（Actions → Threads 每日發文 → 那一次 → Artifacts），不會碰 Threads。

注意：排程只在 main 分支上跑，這個工作流程要合進 main 之後才會每天自動執行。

### 站長要做的（一次）

1. **建 Meta 開發者應用程式**：到 developers.facebook.com → 我的應用程式 → 建立應用程式 → 使用案例選「存取 Threads API」。
2. **權限**：在使用案例裡加上 `threads_basic`、`threads_content_publish`、`threads_manage_replies`、`threads_read_replies`（發留言前先查自己回過了沒，避免重複留言）。
3. **把自己加成測試人員**：應用程式角色 → 新增 Threads 測試人員（填自己的 Threads 帳號），再到 Threads App 的「設定 → 帳號 → 網站權限 → 邀請」接受。
4. **產生權杖**：用 Meta 的「Threads API 測試工具」或授權網址登入取得短效權杖，再換成長效權杖（60 天）。拿到兩樣東西：長效權杖、自己的 Threads 使用者 id（數字）。
5. **放進 GitHub**（repo → Settings → Secrets and variables → Actions）：
   - Secrets：`THREADS_ACCESS_TOKEN`＝長效權杖；`THREADS_USER_ID`＝使用者 id（可以不填，會用權杖查）。
   - 權杖不要貼在對話、Issue 或程式裡。
6. **先手動試跑一次**：Actions → Threads 每日發文 → Run workflow，mode 選 `dry-run`，看摘要。
7. **打開正式發佈**：Variables 新增 `THREADS_PUBLISH`＝`1`。之後每天中午自動發。
8. **要停**：把 `THREADS_PUBLISH` 改成 `0` 或刪掉，馬上回到只試跑。

### 權杖到期

長效權杖 60 天到期；用了 24 小時以上、還沒過期時可以續期。
- **自動續期（建議）**：另外建一個 fine-grained token（只給這個 repo 的 Secrets: Read and write 權限），存成 secret `THREADS_SECRETS_PAT`。正式發佈時，剩不到 20 天就自動續期並寫回 `THREADS_ACCESS_TOKEN`。
- **沒有 `THREADS_SECRETS_PAT`**：只在摘要寫剩幾天，不會續期。快到期時自己重做第 4–5 步。

### 站長自己選的題

`packages/server/threads_picks.json`：

```json
{ "version": 1, "picks": { "2026-11-25": "Y39DE-1-5" } }
```

- 一行「日期（台北）: 題號」。沒列的日子照自動計畫。
- 選了週三（1-5）那局，週四的 3-5 自動接同一局；週五（2-5）和週六（4-5）也一樣。
- 題號不是那天主題能出的題就忽略、照計畫，摘要會寫原因。
- 已經發出去的日子不受影響。
- 私人選題頁的選擇，由 Claude 每天同步進這個檔案。

### 第一則留言

ChatGPT 寫在 `docs/threads/comments/<日期>.md`，格式見那個資料夾的 README。沒有檔案時用備案：一句觀念加建議文章的網址。

### 手動發的那一天

2026-11-17 是站長手動發的。隔天的 A 會自動去最近的貼文裡找「題號 36AKW-2-5」來引用，不用做什麼。

找不到時（例如那篇被刪了、或超過最近 25 篇），可以手動補記：Actions → Threads 每日發文 → Run workflow，mode 選 `record-manual`、date 填那一天、post_id 填貼文 id（空白就用權杖去找）。

### 圖放哪裡

Threads API 只收公開網址的圖。圖推到這個 repo 的 `threads-state` 分支（`images/<日期>.png`），用 `raw.githubusercontent.com/<repo>/<commit>/images/<日期>.png` 給 Threads 抓。
- repo 本來就公開，不用另外開服務或碰正式網站的部署。
- 圖只有座位和牌譜記號，跟貼文一樣是公開內容。
- 網址綁 commit，不會被之後的檔案蓋掉。
- 只在正式發的那一刻才推，試跑不推。

## 站長選局（2026-11-17）

站長 11/17：「我如果需要 看到未來一週 甚至一個月的文章安排 並且我可以自己選擇牌譜(從候選名單中挑 盡量是S高一點的優先)」，
以及「不能先用條列式表格呈現牌譜就好嗎 (像googlesheet 那樣) 我可以先用條件來篩出自己想要的」。

- **S 是什麼：** 網站的「陣容強度」（站長 10/31）：每局賽前十個座位在當時玩家池裡的 PR 平均，S ≥ 65 是網站的高強度局。
  來源是 `games_cache.json` 每局的 `lineup[1]`（S×10），用 `generate_cache.py record_fingerprint` 同一個指紋對上題庫的局（`src/bots/threads/strength.ts`）。
  題庫 1,778 局有 1,218 局對得上 S；對不上或不評分的局 S 顯示「—」，排在最後。牌譜整併（#38）之後 1,777 局有網站牌譜頁。
- **選局頁：** 站長私人的 claude.ai 頁面（不在公開網站上），兩個分頁：
  - **日曆：** 從第一篇（11/17）起 28 天，每天目前的題目和照 S 由高到低的前 15 個藍方視角候選（刺殺題是刺客），再補 5 個有網站牌譜頁、S 最高的。
  - **牌譜表：** 題庫每一局一列（像試算表），欄位：題號、S、網站牌譜、第 1–5 局任務（`oox`／`ooox`／`ooxx`…，沒打到的局空白）、結果（三紅／三藍死（刺中）／三藍活）、
    刺殺座位、1–0 家角色、派西維爾位置、派西資訊（兩根拇指＝梅林、莫甘娜）、梅林位置、湖（`0>5x`：0 家湖 5 家說壞）、可出題型（1-5、1-5→3-5、2-5、2-5→4-5、3-5、第4局忠臣5人、第5局、刺殺、派西）。
    每欄都能篩（任務、角色、座位、題型多選；題號、拇指、湖文字含；S 最低值），每一局「選給…」只列主題對得上、還沒鎖住的日子。
  - 頁面附帶 `candidates.json`、`games.json`（`threads:candidates` 產生）；站長選的寫進頁面資料庫的 `picks/<日期>`（`{ date, exerciseId, nextExerciseId, chosenAt, … }`），只有擁有者能寫。
  - 週三、週五選了能連著打的局，隔天自動接同一局；週四、週六另選就改出獨立的題目。已經貼出去的日子（`THREADS_POSTED`，11/17 36AKW-2-5）和今天以前的日子鎖住。
- **選擇的正本：** commit 進 repo 的 `packages/server/threads_picks.json`（自動發佈 #48 的格式）：`{ "version": 1, "picks": { "YYYY-MM-DD": "<題號>" } }`。
  產生器只有一條選題的路：`pickOverride`（存下來＝已經發出去的那一天優先；選的題不是那天主題能出的就照計畫，原因寫進 `warnings`）。
  選局頁列出來的題號（`optionsFor`）跟 `pickOverride` 用同一套池子，一定接受。
- **腳本：** `threads:candidates`（`--picks` 預設 `threads_picks.json`；輸出 `candidates.json`、`games.json`，不進 git）、`threads:draft -- --picks <檔>`。
  兩個腳本讀同一份輸入（`src/bots/threads/inputs.ts`）：選的每一天都用（含今天和過去的日子：前一天選的今天的題目、昨天的答案都要對上），
  已經發出去的以存下來的草稿（`threads_drafts/<日期>.json`；`threads:candidates` 用 `--drafts` 指定）為準。
  `--picks` 也接受選局頁資料庫匯出的 `[{ "date": …, "exerciseId": … }]`。

### 每天早上 8 點（台北）的工作

1. 讀選局頁資料庫的 `picks` 集合（ArtifactData `list`，collection `picks`），今天之後的日子
   同步進 `packages/server/threads_picks.json`（`picksFileBody`，日期排好；今天和過去的日子保留檔案裡原本的，不刪）；有變動就 commit（選擇的正本在 repo）。
2. 產生今天的草稿（或由自動發佈 #48 讀 `threads_picks.json` 發文）。
3. 重跑 `threads:candidates -- --today <今天>`，把新的 `candidates.json`、`games.json` 更新到選局頁（今天鎖住、後面的日子照選擇重排）。
