## 1. 自我對打方法

- **對局**：`SelfPlayEngine` 10 人局（刺、娜、德、奧、派、梅 + 4 忠臣，含湖中女神），agent = `HeuristicAgent`（走 ForwardAgent；湖目標與宣告走 agent 層 `pickLakeTarget` / `declareLake`，所以每個 agent 的 tuning 都生效）。
- **配對設計**：每組種子跑三局，三局的座位順序與角色完全相同（引擎的洗牌在 `(seed, 局號)` 播種的 PRNG 下進行）：
  - A：variant 坐紅方、baseline 坐藍方；
  - B：baseline 坐紅方、variant 坐藍方；
  - C：兩邊都是 baseline（配對對照）。
- **共用亂數**：每個決策在 `(seed, 局號, 座位, 階段, 回合, 提議數, 任務數, 湖數, 當前隊伍)` 播種的 PRNG 下執行（同 agreementBenchmark 的播種方式），所以同一情境下 baseline 兩邊做一樣的決定；variant 與 baseline 相同時三局完全一致（control 列合計恰為 50.0%）。
- **勝負**：引擎的最終結果 — 三紅或三藍死 = 紅勝，三藍活 = 藍勝（Edward 2026-10-12 裁定的「最終」口徑）。另列任務結算（三紅率）與刺殺結算（三藍局刺中率）。
- **指標**：
  - **紅方立場** = A 局紅勝率，對照 = C 局紅勝率；差 = 逐種子配對差（A − C）的平均與常態近似 95% 區間。
  - **藍方立場** = B 局藍勝率，對照 = C 局藍勝率；差 = B − C。
  - **合計勝率** = 逐種子 (A 紅勝 + B 藍勝) / 2 的平均（variant 一半時間當紅、一半當藍，對手都是 baseline），區間為逐種子常態近似；variant = baseline 時恰為 50%。
  - 注意不能拿 A 對 B 比：每局都是 variant 一邊、baseline 另一邊，A 的紅勝率與 B 的藍勝率加起來恆為「合計」，兩個立場的「差」會是同一個數字；所以立場要對 C。
- **局數**：每開關 5000 組種子 × 3 = 15000 局（任務要求每組至少 2000 局）；10 人局約 35 ms 一局（GameEngine 的事件 log 在跑分時關掉）。
- **自我對打的紅方極強**：baseline 自打自紅勝約 88%（三紅率約 84%），真人 10 人局紅勝約 70%、三紅約 45%。藍方立場的數字因此都很小（約 12%），差距要看配對差的區間而不是絕對值。

## 3. 刺殺選人模型

### 方法

- **資料**：`sheets_cache.json` 的 `牌譜` 經 `parseReplayGame` 嚴格重播的 1970 局 10 人局中，到達三藍且有刺殺目標的 **1048 局**。標籤 = 真正的梅林座位；輸入 = 刺客在刺殺階段的觀測（`buildReplayObservation`：公開歷史 + 刺客的 `knownEvils`（娜、德）+ 刺殺階段的完整紅方名單 `allEvilIds`，後者只用來排除候選與判斷湖主陣營）。**不讀 roleMap**。
- **切分**：以對局為單位，`fnv1a("assassin|" + 流水號) mod 100 < 70` 為訓練（731 局）、其餘測試（317 局），固定不隨機。
- **模型**：條件邏輯回歸（每局在 6 個好人候選上做 softmax：P(c = 梅林) ∝ exp(w · x_c)），39 個特徵（`src/ai/assassin/AssassinModel.ts` 的 `ASSASSIN_FEATURE_NAMES`：被提議比例、成功 / 失敗任務數、是否從未在失敗隊、隊伍含可見紅的比例、紅方隊長選到的比例、隊外白 / 隊內黑比例、對含刺客 / 含隊友隊伍的投票、對乾淨隊伍的隊外白 / 隊內黑、票與結果一致度、與刺客同票比例、隊長次數與派隊內容、被紅方 / 非紅方湖主宣告好壞、當過湖主、湖了紅方、座位 one-hot）。訓練列標準化後用全批次 Adam 最佳化負對數概似 + L2；λ 由訓練局 5 折交叉驗證（對數概似）在 {0.001…1} 選出 **λ = 0.1**；標準化折回原始尺度權重寫入 `assassinModelWeights.ts`（softmax 不需要偏置）。不引入新依賴。
- **接線**：`AgentTuning.assassinModel` 打開時 `HeuristicAgent.assassinate` 在 `allEvilIds` 過濾後改用 `pickAssassinTargetByModel`（同分依座位序）；ForwardAgent 的刺殺本來就委派給 baseline，所以兩條路徑一致。

## 5. 限制

- 自我對打的對手是機器人，紅方 88% 勝率代表機器人藍方很弱；「不變弱」是對機器人對手而言，對真人的效果要靠一致性基準與上線後的戰績（`/stats`）觀察。
- （2026-10-13 已修正）正式伺服器的機器人湖目標原本是隨機、湖宣告走 `GameServer` 自己的規則（好人說實話、紅方反說），湖的開關只影響自我對打與基準。現在 `GameServer.pickBotLakeTarget` / `decideBotLakeClaim` 先問機器人自己的 agent（`HeuristicAgent.pickLakeTarget` / `declareLake`，與自我對打相同的 `LakePolicy`），agent 不存在、沒有湖的介面、出錯或給了不合法的目標時才退回舊做法；`AVALON_BOT_LAKE_VIA_AGENT=0` 可整個退回舊做法（第 6.3 節）。
- 自我對打裡「把湖留在紅方」本身可能量不到好處：機器人好人拿湖後的宣告也會被同一條硬3 規則誤傷（誠實的好人宣某人藍、之前帶隊沒放他 → 一樣被當成可疑，這條規則連湖之前帶的隊也算），所以讓藍方少拿湖在自我對打裡不一定對藍方不利。這可能是紅方湖策略在自我對打裡變弱的原因之一，但沒有直接驗證；這是機器人對手的特性，對真人的效果要看一致性基準與上線戰績（第 6 節）。
- 刺殺模型的訓練集只有 731 局；特徵全是手寫的計數比例，沒有用到座位以外的玩家身分（故意不用名字，避免針對特定玩家）。
- 一致性基準的 ED 樣本小（刺殺 17 筆、湖宣告 14 筆），ED 專屬的結論看 Sin / top / population 比較穩。

**最後勝負（描述性，有混淆：策略是看局勢選的，不能當因果）**：有隊友可湖時，湖隊友的紅方最終勝率 74.3% [68.3%, 79.6%] 168/226，湖藍方 69.2% [65.4%, 72.8%] 412/595（兩邊都含各種宣告）。把「可湖的隊友是否在失敗任務上」固定後差距縮小：隊友在失敗任務上時湖隊友 81.2% [74.6%, 86.4%] 134/165、湖藍方 78.0% [73.4%, 81.9%] 283/363（差 3.2pp，區間重疊）；隊友乾淨時 55.7% [43.3%, 67.5%] 34/61 對 55.6% [49.2%, 61.9%] 129/232。依宣告細分（看得到隊友的紅方全部的湖）：湖隊友宣好 76.6% 134/175、湖藍方說實話 68.1% 292/429、湖藍方宣紅 73.6% 106/144。

**解讀**：真人有隊友可湖時只有約四分之一去湖隊友，跟亂湖差不多（期望值 22%），所以「盡量湖隊友」是 Edward 的**規範**，不是牌譜上的多數打法；宣告則清楚：隊友幾乎都宣好（84%），湖到藍方大多說實話（75%）；宣紅的比例在「自己和對方一起出過失敗任務、紅方只差一局」時最高，但沒有任何情境過半。

### 6.2 策略（`LakePolicy.pickEvilLakeTargetHuman` / `decideEvilLakeClaimHuman`）

**注意：本節描述的是只開 `evilLakeHumanStrategy` 時的規則。** 2026-10-13 第二輪之後的正式預設另外打開 `evilLakeFrameHumanRate`（湖目標不再為了嫁禍去找一起出過失敗任務的人，湖到藍方時依情境以真人比例**亂數**宣紅，取代下面第 3 點的固定嫁禍規則）與 `evilVouchFollowUp`（宣告之後自己派的隊與投票照宣告走），見第 8 節。

全部是固定規則，不用亂數（開關關閉時原本的 `Math.random` 呼叫順序完全不變）：

1. **湖誰**：有看得到的隊友可湖、而且之後還有湖（R2、R3 後的湖）→ 湖隊友。有兩位時，先選**自己帶隊時最少把他拿掉的那位**（每次都放在隊上 = 0 次；替自己沒帶的人背書是破綻），再選比較被懷疑的（宣好能洗掉最多壓力），再依座位。
2. **最後一次湖**（R4 後，被湖的人之後拿不到湖，留在紅方已沒有價值）→ 只要有一位隊友帶一點嫌疑（嫌疑分數 > 0）就湖他洗白、幫他上最後一個任務；隊友全都毫無嫌疑才改湖藍方。實際上到這時（比分 2:2）幾乎每位隊友都有一點嫌疑：真人牌局裡最後一次湖、有隊友可湖的 147 次，這條規則有 143 次還是湖隊友（真人只有 26 次，17.7%）；自我對打裡則是每次都湖隊友。所以實際行為幾乎等於「最後一次也湖隊友」，與第 1 點只差在極少數情況。
3. **湖藍方**（沒有隊友可湖，或第 2 點改湖藍方）：紅方已拿兩局、而且有藍方跟自己一起出過失敗任務 → 湖那位（最可疑的優先）並**宣紅**（嫁禍、讓資訊變混亂）；否則照第 1 點的背書順序挑藍方並**說實話宣好**（買好感）。
4. **宣告**：隊友一律宣好；湖到原本看不見的紅方（奧伯倫，或奧伯倫湖到任何紅方）宣好掩護；藍方照第 3 點。
5. **奧伯倫**看不到隊友，所以永遠走第 3 點，用的是同一個順序（紅方聽牌時先找一起出過失敗任務的人嫁禍，否則先選自己帶隊時最少拿掉的人，再看嫌疑），**不是**「挑最可疑的人」；湖到紅就宣好，湖到藍照第 3 點。這個順序找不到隱藏的紅方：真人牌局裡奧伯倫持湖的 289 次，這條規則湖到的人是紅方的只有 27.7%（80/289），比在合法目標裡亂挑（32.8%）和真人（33.6%）都低；改成單純湖最可疑的人也一樣是 27.7%（奧伯倫自己出的失敗會讓同隊的藍方背上嫌疑，可能是原因）。自我對打裡機器人奧伯倫湖到紅方的比例見 6.4。
6. **與其他開關的關係**：開關打開時取代舊的紅方湖目標規則（包含 `AVALON_EVIL_LAKE_BRING_FRIEND=0`）；宣告上若同時打開 `evilLakeClaimAlwaysGood`，以「一律宣好」為準（目標仍由本策略決定）。好人持湖完全不受影響。
7. 戰術組合可用 `AVALON_EVIL_LAKE_HUMAN_VARIANT`（例如 `chaos=never`）切換，**只有基準腳本**（`selfPlayStrength.ts`、`agreementBenchmark.ts`、`redLakeDiagnosis.ts`）會讀；伺服器不讀，設在正式環境也沒有作用。明確設成非預設值的那一項優先於第二輪的開關（`LakePolicy.evilLakeHumanOptionsFor`）：在現在的正式預設下設 `chaos=never`，量到的就是 `chaos=never`，不會被 `evilLakeFrameHumanRate` 蓋掉；要回到預設的 `chaos=frame`，改用 `--flag evilLakeFrameHumanRate=0`。

### 6.3 線上對局

`GameServer` 的機器人湖原本是隨機選目標、紅方把看到的真相反說，湖的開關（含已採用的 `goodLakeTargetMostSuspicious`）對線上都沒有作用。現在 `pickBotLakeTarget` / `decideBotLakeClaim` 用伺服器原有的觀測建構（`buildBotObservation`）問機器人自己的 agent（`pickLakeTarget` / `declareLake`），時間安排與階段流程不變；agent 不存在、沒有湖的介面、出錯或回傳不合法的目標時，退回舊的隨機目標 / 反說規則（`GameServer.botLake.test.ts`）。

上線後的實際變化（當時 `evilLakeHumanStrategy` 預設關；同日打開後，線上紅方機器人改用 6.2 的新策略，第二輪再加上第 8 節的兩個補強，見 6.5）：

- **機器人好人**：湖最可疑的人並說實話（原本隨機湖、說實話）。
- **機器人紅方**：改用自我對打一直在用的舊紅方規則 —— 隊友被懷疑就湖隊友洗白，否則湖最像梅林的人；隊友宣好，對手看像不像梅林決定宣好或宣紅（部分角色帶一點隨機說謊）。**不是** 6.2 的新策略。原本是隨機湖、看到什麼就反說。一致性基準上，舊紅方規則的湖宣告比反說更像真人（population 58.2% vs 45.8%）；但「舊紅方規則 vs 線上反說」的強度沒有量過（自我對打的對照組本來就是舊紅方規則）。
- **要整個退回原本的線上做法**（隨機目標、好人說實話、紅方反說）：`AVALON_BOT_LAKE_VIA_AGENT=0`。**要讓線上紅方機器人退回舊紅方規則**（不用 6.2 的新策略）：`AVALON_TUNING_EVIL_LAKE_HUMAN_STRATEGY=0`；第 8 節的兩個補強只在新湖法打開時有作用，所以這一個變數就等於退回第二輪之前的舊預設。

### 6.5 決定與待決事項

- **第一輪（2026-10-13）依規則不採用**：定案版的湖宣告更像真人（四個群都大幅提高），湖目標只到簡單規則的水準，自我對打換新種子後紅方變弱（五個種子合併 −0.6pp [−0.9pp, −0.3pp]）。
- **Edward 裁定（2026-10-13，原文）**：「1 紅方新湖法先打開 變弱應該從其他地方調整修正 (先像真人 再從策略上提高勝率)」，並問「有沒有可能勝率少是因為他本身策略就沒有進行修正?」→ `DEFAULT_AGENT_TUNING.evilLakeHumanStrategy = true`（legacy 仍關；`AVALON_TUNING_EVIL_LAKE_HUMAN_STRATEGY=0` 可關掉），變弱的原因與從其他紅方決策補回的做法見第 8 節。這是依擁有者裁定、不是依強度規則採用：先像真人。
- **當時列給 Edward 的待決事項**（第 1 點已由上面的裁定回答，其餘的處理見第 8 節）：
  1. 要不要接受這個幅度的變弱（約 −0.6pp，機器人對機器人）換取更像真人的湖宣告。`chaos=never`（藍方一律說實話）與定案版強度相同，宣告更貼近全體玩家與 ED（population 77.2%、ED 85.7%），但機器人就完全不嫁禍（0%），也不像真人；定案版則嫁禍得比真人多很多（6.4 表）。
  2. 真人在有隊友可湖時只有約 24% 去湖隊友（接近亂湖），最後一次湖只有 18%；新策略幾乎每次都湖隊友。這是依裁定的規範做法，不是牌譜多數。若要更像真人，可以收緊最後一次湖的條件（例如隊友在失敗任務上、而且嫌疑不低於中位數才湖他），改了要重跑兩個基準。
  3. 奧伯倫的湖：目前的順序湖到紅方的比例（27.7%）比亂挑（32.8%）還低。要不要改成亂挑或其他規則，由 Edward 決定；改了要重跑。
  4. 機器人的硬3 規則連湖**之前**帶的隊也算、誠實的好人也會被標記（`lakeChainTracker.findRule3Violators`），所以自我對打可能量不到「讓藍方拿不到湖」的好處（第 5 節）。要不要讓硬3 只看湖之後的隊伍，會改變所有好人機器人的判斷、需要另外重跑全部基準，這次沒有動。
  5. 線上機器人湖改由 agent 決定（6.3）：好人改湖最可疑的人、紅方改用舊紅方規則，強度沒有和原本的線上做法比過；不想要可用 `AVALON_BOT_LAKE_VIA_AGENT=0` 退回。

## 7. 好人湖中女神：共同資訊極大化（`goodLakeInfoMax`，2026-10-13）

**Edward 原文（2026-10-13）**：

> 信任鏈的湖中選擇對於一紅一藍時幾乎成立
> 但如果是兩紅時湖中不一定要湖好人, 因為只要任務過了就有鐵四好, 再加上第四局的任務派隊或許能驗證出第五個好人
> 但其實好人湖中的最大原則就是使場上的好人視角(紅方已經相認 沒有視角更清晰的問題 除了奧伯倫) 能夠更清晰 讓藍方不確定性最小化 極大化共同資訊
> 你說我的湖法 不只是出過任務失敗 應該是 "出過任務" & 最有可能是好人/湖下去最有可能讓共同資訊極大化的人

解讀：「一紅一藍」= 湖的時候比分 1:1；「兩紅」= 紅方已拿兩局（第一次湖時 0:2，第二次湖時 1:2）—— 之後只要任務通過，整隊就都是藍（R3 四人 → 鐵四好），R4 的派隊還可能再驗出第五個藍，所以這時的湖不必拿來養信任鏈。好人持湖的目標是讓**藍方共同的視角**更清晰：極小化藍方的不確定性、極大化共同資訊；首選出過任務、最可能是藍、或湖下去最能讓共同資訊變多的人（被湖的人是下一位持湖者，湖到藍就多一位可信的持湖者）。

**結論**：**採用**（`DEFAULT_AGENT_TUNING.goodLakeInfoMax = true`）—— 好人湖目標更像真人（好人持湖的湖目標一致率 ED 18.9→35.1%、Sin 20.3→22.9%、top 12.2→25.8%、population 14.9→24.7%；同一批湖配對比較，top 與 population 的進步顯著，ED 淨多 6 次但 p≈0.07、而且信任鏈項的形式是在同一份牌譜上挑的，Sin 看不出差別，見 7.3），自我對打藍方立場三個種子合併 −0.3pp [−0.6pp, +0.1pp]，區間含 0，依「不能讓它變弱」不算變弱。`goodLakeTargetMostSuspicious` 保留，只在模型找不到一致組合時當退路；`AVALON_TUNING_GOOD_LAKE_INFO_MAX=0` 可關掉（自我對打、一致性基準用 `--flag goodLakeInfoMax=0`）。線上機器人的湖目標也由 agent 決定（第 6.3 節），所以線上好人機器人同時改用新模型。對照組是 2026-10-13 當時的正式預設（紅方湖仍是舊規則），另一項紅方湖的改動合併後要整組重跑。

### 7.2 模型（`src/ai/GoodLakeInfo.ts`，只接在 `LakePolicy` 好人分支）

1. **可能的世界**：10 人、4 紅，持湖者是藍 → 其餘 9 人選 4 個紅的 126 種組合。兩種加權：
   - **持湖者的看法**：加上自己的角色資訊 —— 梅林看得到的紅一定在（只剩莫德雷德不知道）、派西的兩拇指恰好一紅（莫甘娜）；
   - **藍方共同視角**：只用公開資訊，加上「持湖者是藍」（宣告只有在相信持湖者的藍方之間才是共同資訊 —— 這就是信任鏈）。
   兩者都乘上：任務失敗牌的概似 P(失敗牌數 | 隊上紅方人數, 回合)（1970 局真人 10 人局的經驗表，`MISSION_FAIL_COUNTS`；失敗牌多於紅方人數是不可能，通過的任務因此會降低隊員是紅的機率）；先前的湖宣告：持湖者是藍的世界裡宣告必須為真，持湖者是紅的世界裡宣告不帶資訊（兩種宣告各 ½）。先前有人把我宣紅 → 那個人一定是紅。沒用投票（待決事項）。
2. **資訊量**：視角的不確定性 = 除持湖者外每個人「是紅」機率的二元熵總和（bits）。對每個合法目標 c：用持湖者的看法預測湖的結果，結果公開後藍方共同視角的不確定性期望下降 ΔH(c) = U(共同) − Σ_x P_持湖者(c = x) · U(共同 | c = x)。出過任務的人和同隊隊員透過失敗牌數綁在一起，湖到一位也會移動其他隊員的機率 —— 模型裡「出過任務」的偏好就從這裡來，沒有另外加分（模型湖到出過任務的人 93.7%，已經比真人 79.8% 高）。忠臣持湖時（持湖者的看法 = 共同視角）ΔH 是互資訊，一定 ≥ 0；梅林、派西用自己的私人資訊預測結果，結果對藍方來說可能是意外，ΔH 可以略為負（隨機情境裡最低約 −0.05 bits，都出現在持湖者已認定很可能是紅的人身上）；V 取 max(0, ·)，這些人的信任鏈項本來就是負的，不影響選人。
3. **信任鏈**：被湖的人是下一位持湖者。之後還有湖時，目標是藍 → 多一位可信的持湖者（值一次湖 V）：T(c) = λ · (1 − 2 · P_持湖者(c 是紅)) · V，V = max(0, 目前最好的 ΔH)。V 對每個候選人都一樣，所以 T(c) = 2λ · P_持湖者(c 是藍) · V − λV，−λV 不會改變選誰：這其實只是**一個**選擇 —— 在「P(藍) · V」上放權重 2λ。（原本寫成「湖到藍 +V、湖到紅會說謊 −V」，但「說謊的代價」不是另一個成分，結果和只算好處、權重加倍完全相同。）
4. **比分**：λ = 1（等於 P(藍) · V 權重 2）；**兩紅**（紅方已拿兩局）與**最後一次湖**時 λ = 0，只看資訊量。2:0、2:1 時下一次湖只有在紅方拿下一局時才會發生，λ 沒有乘上這個機率（待決事項）。
5. **選人**：在避開名單（梅林看得到的紅、派西的兩拇指，照舊）以外的合法目標取 ΔH + T 最大者；同分（差 < 1e-9）依座位序。決定性、不用亂數。若沒有任何組合與記錄相符（記錄矛盾，先拿掉湖宣告再試），退回 `goodLakeTargetMostSuspicious` / 舊規則。
6. **與其他開關的關係**：`goodLakeInfoMax` 打開時優先於 `goodLakeTargetMostSuspicious`（後者只在模型找不到一致組合時當退路）；紅方持湖、湖宣告都不受影響。

信任鏈項的權重是在牌譜上比較幾種寫法後選的（`goodLakeStudy.ts` 的 “same target as the human: agent rules and model forms” 表，同分依座位序，與模型相同；好人持湖的湖目標一致率，ED / Sin / top / population）：只看資訊量（λ = 0）18.9 / 12.7 / 11.3 / 13.7%；P(藍) · V 權重 1：27.0 / 21.2 / 21.4 / 20.7%；**權重 2（定案，= λ(1 − 2p)V、λ = 1；兩者 2383 次選人完全相同）35.1 / 22.9 / 25.8 / 24.7%**；權重 4（λ = 2）27.0 / 18.6 / 24.9 / 24.5%；定案形式但兩紅時也加信任鏈項 27.0 / 19.5 / 24.1 / 23.4%（兩紅時變差：0:2 population 15.0→10.1%、top 13.6→8.0%，1:2 population 14.4→12.3%）；定案形式再乘「之後還剩幾次湖」27.0 / 17.8 / 24.9 / 24.8%；單純湖「最可能是藍」10.8 / 11.9 / 21.2 / 19.6%、「出過任務中最可能是藍」16.2 / 12.7 / 23.9 / 23.1%。因為是在同一份牌譜上挑的，一致率數字偏樂觀：定案形式和「乘剩幾次湖」在 population 幾乎一樣（24.7 vs 24.8%），兩者主要差在 ED（13 vs 10 次）；ED 只有 37 次，差 1 次就是 2.7 個百分點。

**簡答**

1. **變弱的路徑是「湖留在紅方」× 好人機器人的「硬3」規則**（`lakeChainTracker.findRule3Violators`：誰宣某人藍、自己帶過的隊卻沒放那個人，就被當成可疑到 0.85 以上）。
   - 有硬3、開新湖法時，紅方 −0.92pp [−1.32pp, −0.52pp]（seed 99 + 4242，10000 組）。
   - 只把**湖目標**交回舊規則（宣告保留新做法），差距就消失：−0.03pp [−0.18pp, +0.12pp]，佔 97% [79%, 116%]。
   - 把硬3 整個關掉也一樣：+0.21pp [−0.09pp, +0.51pp]，佔 123% [90%, 173%]。
   - 紅方的湖宣告本身幾乎不影響勝負。**最後一次湖與奧伯倫的新做法反而是加分**：各自交回舊規則時，紅方再弱 1.48pp / 0.35pp。
2. **為什麼（兩條線）**：硬3 連「湖之前」帶的隊也算，10 人局 R1 的隊只有 3 人，帶過隊的人很容易漏掉日後要宣藍的對象。硬3 整體對藍方有利：舊預設自打自時關掉它，紅方 +0.70pp。它透過兩條線作用，新湖法在兩條線上都吃虧（拆線消融只跑 seed 99，該種子差距 −1.00pp）：
   - (a) **藍方自傷變少**：舊規則常把湖交給藍方（有隊友可湖時只湖隊友 42%），誠實的藍方持湖者一宣「某人是藍」，就可能被好人機器人自己標成可疑、踢出後面的任務。新湖法把湖留在紅方（第二、三次湖紅方持湖 49% / 74%，舊規則 36% / 35%），藍方少拿湖，也就少自傷。只讓硬3 標記紅方持湖者時，藍方自傷這條線在舊預設讓藍方少贏 1.42pp，在新湖法只有 0.82pp，佔差距 **60%** [22%, 132%]。
   - (b) **紅方持湖者被抓到的代價變大**：只讓硬3 標記藍方持湖者（拿掉抓紅方這條）時，舊預設紅方 +2.08pp、新湖法紅方 +2.92pp，佔差距 **84%** [37%, 136%]。新湖法的紅方持湖者被標記的次數其實比較少（遊戲結束時 2682 vs 3398 人次），但被抓到時損失更大，推測是因為被他背書的多半是隊友。

   兩條線加起來超過 100%，彼此有交互作用；只跑一個種子，區間也很寬。
3. **「是不是策略本身沒修正」：有一部分是。** (b) 是紅方自己的破綻：機器人紅方替自己沒派過的隊友背書。
   - **宣告之後**的不一致是真人不會犯的。只開新湖法時，紅方持湖者宣藍後自己帶隊只有 46.7%（789/1691）會放被宣的人（真人：宣隊友 78.7%、宣藍方 92.5%）；自己不在隊上時，漏掉被宣者的隊只反對 69.7%（13216/18957）（真人 84.3% / 83.4%）。
   - 補上這一點（`evilVouchFollowUp`）有效，而且決勝窗口也守信的版本補得更多：
     - 「窗口不適用」的版本：31337 + 8080 + 2718 合併邊際 +0.35pp [+0.14pp, +0.55pp]，約補回只開新湖法差距的 34% [14%, 61%]。
     - 「窗口也照做」的版本（加上 `evilLakeFrameHumanRate`，即正式預設）：31337 + 16180 + 14142 合併 **+0.54pp [+0.25pp, +0.83pp]**，約補回 64% [33%, 109%]。
     - 兩個版本只看確認種子也都不含 0（+0.36pp [+0.10pp, +0.62pp] / +0.54pp [+0.19pp, +0.89pp]）。

   - **宣告之前**的部分，湖後補不回來：機器人紅方當隊長時 R1 從不放隊友（真人 43.9%），只要 R1 帶過隊，之後替隊友背書就違反硬3（第 8.6 節第 6 點）。
   - (a) 跟紅方策略無關，是好人機器人的硬3 在舊規則下「誤傷自己人」的機會變少了。

   兩條都是機器人對機器人的現象。
4. **結果**：正式預設改為舊預設 + `evilLakeHumanStrategy` + `evilVouchFollowUp`（決勝窗口也照做）+ `evilLakeFrameHumanRate`。

### 8.1 方法

- **工具**：`scripts/redLakeDiagnosis.ts`。
  - 每組種子只跑 `selfPlayStrength.ts` 的 A（variant 當紅、baseline 當藍）與 C（baseline 自打自）兩局，播種完全相同，同一組種子兩支腳本的 A、C 結果逐局一致。
  - 正式預設（「窗口也照做」改成程式預設之後，不設任何環境變數）在 seed 14142 用 `selfPlayStrength.ts` 重跑一次：A 紅勝 4620/5000、C 4667/5000、紅方差 −0.94pp [−1.57pp, −0.31pp]，與診斷腳本（設 `AVALON_VOUCH_FOLLOW_UP_VARIANT=decisiveWindow=follow` 的那次）逐局相同；B 局 = C 局（藍方差 +0.0pp），合計 49.5% [49.2%, 49.8%]。一致性基準不加任何旗標重跑，也和設環境變數的那次逐項相同。
  - 紅方開關不影響藍方立場（B 局 = C 局），所以紅方差 A−C 就是 `selfPlayStrength.ts` 的紅方立場差。
  - 另外逐局記錄：
    - 湖鏈：持湖者陣營 / 角色、湖到誰、宣告；
    - 硬3 旗標：≥0.85，依陣營、依「第幾回合之前」；
    - 紅方宣藍之後，自己派的隊是否放被宣的人，以及之後對「漏掉被宣者的隊」怎麼投。投票分成「自己不在隊上」「自己在隊上」「自己派的隊」，並分出紅方決勝窗口內外；
    - 湖後任務上的紅方人數；
    - A、C 勝負翻轉的種子各有哪些特徵。
  - `--trace 種子:局號` 逐回合印出一局。
- **消融**（只給腳本用，伺服器不讀）：
  - `--rule3 off|redOnly|blueOnly|postlake`（`lakeChainTracker.setRule3DiagnosticOptions`）：硬3 全關 / 只會標記紅方持湖者 / 只會標記藍方持湖者 / 只算宣告之後帶的隊。A、C 兩局、兩邊所有機器人一起套用。
  - `AVALON_EVIL_LAKE_HUMAN_VARIANT="target=legacy"`、`"lastLake=legacy"`、`"oberon=legacy"`：把新湖法的某一部分交回舊規則。
  - 每個消融都在同一組種子上重跑 A、C。逐局算「預設的 A−C」減「消融後的 A−C」，再除以預設的差，就是這個機制佔的份額；負的份額表示這部分的新做法其實在幫紅方。
  - 份額的 95% 區間是逐局配對的 bootstrap：5000 次重抽，取百分位數，分子分母一起重抽。
  - 補強開關的份額用選版本 + 確認的三個種子量（對「只開新湖法」的逐局邊際效果）。
- **種子**：
  - 診斷用第一輪已經用過、紅方差整個在 0 以下的 seed 99 與 4242（各 5000 組，共 10000 組），不消耗新種子。
  - 補強開關在 seed 31337 選版本，再用沒用過的 8080、2718 確認（各 5000 組），以三個種子合併判定。
  - 審查修正後改選的「決勝窗口也照做」用沒用過的 16180、14142 確認（各 5000 組）。最後再把它在 8080、2718 上也跑一次，只用來報五個種子合併的數字，不影響採用判定。
  - 小型試跑只有一個，種子也記下：`chaos=frameNoHunt` 用 seed 31337 的 1000 組，只看嫁禍比例，不判強度。
  - 所有自我對打的 ForwardAgent 都是 0 次 fallback。

- 藍方持湖者：C 局 3085、A 局 2153。

  4. **`evilLakeFrameHumanRate` 的兩種「像真人」**：

     - 往真人靠（R1 有時放隊友）可能同時更像真人、又減少被硬3 抓到，但也可能讓 R1 更容易失敗被看穿。本輪沒有量；要做得另開開關，照同樣的種子規則驗證。

## 9. 整合後的正式預設：紅方第二輪 + 好人湖一起重跑（2026-10-13）
