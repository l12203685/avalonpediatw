# 改機器人前必查：規則與裁定清單

改任何機器人邏輯（信念、派隊、投票、湖、刺殺）或伺服器的可見性之前，先逐條對照。規則來源是
`docs/avalon-wiki/入門基礎/遊戲基本規則與流程.md` 與 `鐵邏輯_正邏輯_反邏輯.md`；裁定來源是 Edward。
2026-10-26 起設立：當天幾個錯誤（刺殺階段看不到奧伯倫、強制提議不算、用列舉猜莫德雷德）都是基本規則。

## 1. 遊戲規則（規則書）

| 項目 | 規則 | 程式 |
|---|---|---|
| 勝利 | 藍方：三藍且梅林沒被刺中；紅方：三紅、同一局反對 5 次、或刺中梅林 | `GameEngine.ts` |
| 夜晚視野 | 奧伯倫以外的紅方互認；梅林看到莫德雷德以外的所有紅方（含奧伯倫）；派西看到梅林與莫甘娜兩根拇指、分不出誰是誰 | `GameServer.getVisiblePlayerIds`、`types.ts` knownEvils / knownWizards |
| 投票 | 贊成過半才出任務；反對累積 5 次紅方勝 → 第 5 次提議是強制提議，但隊長仍自己選人 | `GameEngine.ts`、1G 刺殺算進強制提議 |
| 任務牌 | 藍方只能出成功；紅方可選；一張失敗就開紅，7 人以上第 4 局要兩張 | `questFailsRequired`；機器人判斷用失敗張數（INV-B3） |
| 湖中女神 | 第 2、3、4 局任務後使用；從 0 家開始；不能湖拿過湖的人；被湖者必須交出真實陣營；持湖者可以宣告、可以說謊、可以不宣告；湖權交給被湖者 | `GameEngine.ts` ladyOfTheLakeUsed；`LakePolicy.ts` |
| 刺殺 | 三藍後進行；紅方可透過發言得知彼此角色，等同所有紅方（含奧伯倫）一起翻牌；最後由刺客決定；刺紅方隊友不算 | `GameServer.sanitizeRoomForPlayer`（state 'discussion' 紅方互見角色）；觀測 `allEvilRoles` |

## 2. 鐵邏輯（社群公認、當作確定）

- 資訊權重：任務結果 > 湖中女神 > 派票 ≥ 黑白球 ≥ 發言 ≥ 狀態。
- x 張失敗 ⇒ 隊上至少 x 紅。
- 藍方湖不說謊：好湖好、壞湖好、壞湖壞；「好人持湖者不可能為真」的宣告會讓持湖者自曝。

## 3. Edward 裁定（當作確定；新裁定加在這裡）

- 兩局失敗後任務成功 ⇒ 隊上紅方不足以讓任務失敗（不會刻意拖延；一般局 = 全好）。（10/26）
- 還湖：A 湖 B 說壞，B 要把湖交給確定是好人的人；不還湖 = 認壞，但不代表 A 是好人。湖不會湖已經確認身分的人，唯一例外是還湖。（10/26）
- 刺殺：派過梅林看得到的紅（刺殺階段已翻牌：莫德雷德以外的紅方）的隊長排除在選項外，第 5 次強制提議也算；所有人都派過才看分數。（10/26）
  - 修改（10/28）：第 1、2 局非強制的提議（正常票一定否決）不算——反制派拇指躲刺；第 5 次強制提議照算。
- 已公開確定是紅的持湖者不宣告。（10/26）
- 派西沒有資訊時預設不派拇指；派西的湖 = 藍方的湖；R1–R2 一律正常票。（10/14）
- 兩紅時好人湖只看資訊量；硬3 只用湖之後的行動。（10/14）
- 機器人改版順序：邏輯正確 > 像真人 > 強度（強度只量不擋）。（10/14）
- 優化迴圈（10/27–28）：藍方優化 → 跑 x 萬局 → 紅方優化 → 跑 y 萬局 → 藍方 … 持續遞迴；目標是期望勝率
  Σ 抽角機率 × 抽位置機率 × 勝率；收斂後放大 x、y；私下跑，練習台只用來和真人對戰。流程見 `docs/ai/optimization_loop.md`。
- 資訊流是層層包覆的（10/26）：每個時間點的決策，包含前一個時間點的全部資訊，而前一個時間點又包含它之前的
  全部資訊流。例：1-2 的決策包含 {1-1}；1-3 包含 {1-1} 與 {1-2} = {1 家的資訊與決策} 與 {2 家對「1 家的資訊與決策」
  的解讀與決策}；1-4 再往下包。派隊、黑白球、任務結果、湖、宣告都是資訊流的一部分。資訊不是斷點。

## 4. 自我檢查

1. 這個推論在「規則」或「鐵邏輯」或「裁定」裡找得到根據嗎？找不到就是機率，不能當確定。
2. 這一步的人「當時」知道什麼，而且這份「知道」是怎麼一層一層包起來的？
   - 當下可見的完整紀錄（夜晚視野、刺殺階段翻牌後、湖的私人結果）只是最外層。
   - 每一個先前的決策（派隊、黑白球、湖、宣告），都要用「那個人當時知道的資訊流」去解讀：他看到前面所有人的
     決策、以及他對那些決策的解讀，才做出這一步。解讀第 t 步，要用到第 1 … t−1 步各自的資訊流。
   - 不能把整段歷史攤平成一張表、或用「越新權重越高」代替；也不能拿後來才知道的事（例：湖後的結果）去解讀先前
     的決策（硬3 只看湖後就是這個原因）。
3. 真人局一定有人不照約定（說謊的好人、不還湖、拖延）：確定性層的約定要能退回（L1 → L0），而且不能套在「自己知道不成立」的人身上（例：被說壞的好人自己）。
4. 伺服器拒絕的動作（刺紅方隊友、湖拿過湖的人），真人畫面上要看得出來為什麼不能選。
